# 按正常使用流程审查前端

审查时间：2026-10-02 至 2026-10-03。应用源码基线：`d7fbe80`。本轮新增流程测试和证据，没有修改应用实现。

## 结论与证据范围

当前前端的主要问题是用户操作不能稳定地组成完整流程：不同页面的“当前对象”不一致，刷新破坏操作上下文，保存和生效的边界不一致，关键反馈不可见。按钮存在、Rust 能执行某个用例、独立模块测试通过，均不能说明普通用户能完成“导入后连上并持续使用”。

后续右键菜单和拥挤问题的专项实测、原版布局差异与修复契约见 `docs/evidence/context-menu-review-2026-10-03/README.md`。该专项已经复现定位、点击关闭和 Esc 问题；完整专项仍受 Debug 原生崩溃影响，未宣称通过。

## 实际走过的完整路径

空白启动 → 通过参数设置保存安全测试端口 → 剪贴板粘贴订阅 A → 菜单导入并确认添加订阅 → 下载出 A1/A2 → 打开订阅设置新增 B → 保存并返回主界面 → 更新全部订阅得到 B1 → 左侧选 B → 更新当前订阅 → 回到全部并选择 A1 → 设置活动节点 → 再次设置同一节点 → 回 A 分组做 TCPing → 修改备注并保存 → 切 B 分组点编辑 → 回全部按 Ctrl+C → 更改双击激活 → 打开设置 → 保存端口改动 → 再编辑端口 → 点应用 → 检查失败后的界面 → 重开设置 → 结束测试进程 → 用相同数据目录启动新测试进程。

这条路径包含真实的跨窗口、后台完成、刷新、再次进入和重开；用户每一步的目标如下。

## 1. 第一次打开：我怎样开始使用

用户此时要知道：有没有节点、是否已有默认节点、所需内核是否就绪、接下来应该在哪个原版入口导入或添加。

实测空节点时“应用”“编辑”等操作仍可点击。截图显示完整操作栏、英文内部列名和 Stopped；空状态只有文字说明，没有与内核就绪状态结合的下一步反馈。核心流程没有明确收敛到“先导入，再选择，再连接”。这是界面设计观察，不把按钮始终可点击本身等同于所有场景下的功能错误。

应固定的流程：

1. 读取持久化数据和实际运行状态后再表达就绪程度；已有配置和空配置分别处理。
2. 在原版布局的空状态和原有菜单/工具栏位置提供明确的导入/添加说明，不增加另一套首页导航。
3. 不满足前置条件的动作应给出就近且可见的原因。若所需内核未安装，说明是哪一个，给出原有更新入口的直接路径。
4. 用户不需要先理解 FRB、revision、内部字段或开发任务编号。

验收时必须覆盖空数据、有节点无默认、有默认无内核、有运行会话四种进入状态。此次实际验证了空数据界面，其余不能凭截图或源码宣称通过。

## 2. 导入后：我是否真的导入成功，下一步在哪

实测订阅 URL 识别、确认、真实下载和两条节点落库可以完成。这一段已有有效链路。

但成功消息的实际位置为 x≈1659..1837，窗口内容宽度只有 1184：**整个提示在可视范围之外**。用户虽然看到新节点，但不知道是否完成、导入了多少、是否有部分失败，也看不到下一步。

应固定的流程：区分分享链接导入、订阅保存和订阅下载；结果在当前上下文可见，明确节点数量和部分失败；保持所选分组/过滤结果，提供明确的默认节点设置路径。导入期间防重复提交，取消或失败不能留下“成功”的旧提示。说明新增节点暂未运行，不能把导入成功当连通成功。

验收：分别用有效分享链接、订阅 URL、多条混合有效/无效文本、空剪贴板和下载失败的合成夹具。每条核对显示结果、持久化结果、可见结果和重开结果；不要只断言存在一条状态 Text。

## 3. 管理订阅：我选中的分组就是这次操作的对象

两项实际失败：

- 在订阅设置新增 B，保存并关闭后，主界面左侧没有 B；执行另一次更新才出现。
- 主界面明确选中 B，点击“更新当前订阅”，没有请求 `/b`，而是提示“请先在订阅设置中选择一个订阅”。该提示也位于可视范围之外。

用户预期只有一个“当前订阅”，实现却分别保存主界面 groupSubId 与订阅设置 selectedId。操作对象必须由入口上下文确定，不能由上次在另一个窗口选择过什么决定。

应固定的流程：新增/编辑/启停订阅后，主界面分组及数量及时更新；主界面更新当前订阅使用主界面当前分组；订阅窗口的行操作使用该行 ID；“全部订阅”明确对应全部启用订阅。后台更新完成后各页面一致，失败保留旧节点，返回后能查到最近结果。

复验路径：新增 B→关闭→左侧立即有 B；选择 B→更新当前→只命中 B；再到设置选 A→回主界面选 B→更新当前仍是 B。更新期间切换主界面分组，任务目标不得跟着变。

## 4. 找节点和编辑：当前看到的节点应当决定操作对象

实测在 A 分组测速或保存 A1 备注后，左侧仍选 A，表格却出现 A1/A2/B1。用户当前视图被后台刷新破坏。

更严重的跨步骤问题：在 A 选中 A1→切到 B，表格只剩 B1，但 A1 仍在 selected 集合里→点“编辑”，打开的实际是 **A1-renamed**。截图 `08-hidden-row-editor.png` 已记录。用户很容易误改或误删另一个分组的节点。

应固定的流程：数据刷新始终保留当前分组、过滤和排序；区分焦点、Shift 锚点、可见选择和默认节点。切组/筛选后按原版规则重新协调选择；任何允许跨视图保留的批量目标，都必须明确呈现完整目标，不能让隐藏选择偷偷参与动作。编辑、删除、导出、测速共同遵守同一目标规则。

复验要用“先在 A 选中，再切 B，再操作”，不能只在一个固定视图里验证按钮。删除只验证确认内容及取消路径，实际破坏性操作另按授权范围执行。

## 5. 测速后选节点：结果应帮助决定，并保留原来的操作位置

实测 A1 的 loopback TCPing 得到 1ms，证明本次测试对真实本地 socket 执行，而非模拟值；这不能证明远端代理或 TLS 可用。测速刷新同时把 B1 带进当前 A 分组视图，是流程失败。

应固定的流程：不同测试的名称、范围、单位和含义可理解；选中测试、当前分组测试、上游定义的全量测试各有明确目标。完成、失败、取消应持续可查，保留分组、排序、选择和视口；结果不足以判断可用时不能引导用户直接“移除无效”。

还需核验：用户自定义测速 URL/并发/超时是否被实际执行，真延迟与速度测试的内核准备链路，测试取消后的迟到结果，切组后结果是否写到正确节点。这些本轮没有真实执行，不能从 TCPing 成功扩展为全部测速通过。

## 6. 设默认并连接：选中、默认、实际运行是三个不同事实

实测 A1 被设置活动后，活动 ID 已保存，而运行时仍为 Stopped；再次设置 A1 则活动 ID 变成 null。原版相同默认节点命令应幂等，切换默认节点走重载请求，依据见上一轮审查。

应固定的流程：

1. 单击选择只改变操作目标，遵守原版双击配置；设置默认节点不会因重复点击而撤销。
2. 按原版触发点执行真实运行配置应用，展示所请求的节点和正在切换的状态。
3. 后端确认成功后，界面显示实际运行节点与连通范围；不是只把选中行染色。
4. 若缺内核、端口冲突、配置错误或应用失败，提示明确原因与恢复入口，说明旧会话是否仍工作。
5. 同一动作的菜单、双击、Enter、托盘入口共用用例；停止会话与选择默认节点有独立的含义。

本轮没有安装或启动内核，因此“真实内核启动并代理成功”仍需独立环境验证。不能把本轮 Stopped 观察描述成成功连接测试。

## 7. 接管流量：内核运行、系统代理、TUN 不能混成一个“已连接”

本轮未操作这部分系统写入。界面显示和源码走查表明它需要作为单独使用流程验收，不能凭平台模块可调用而认为前端已经接好。

正常顺序应明确：用户选择接管方式→检查必要运行前置→执行明确请求→读取实际结果→显示该方式已生效或失败。若内核未准备好，不能先把系统流量引向不存在的监听；TUN 申请、权限、设备准备和真实接管状态必须区分。关闭开关后的恢复应可确认，失败时保留能继续使用的旧状态。

必须分别验收系统代理四模式、仅应用内代理、TUN 的请求/成功/拒绝/失败/恢复路径。普通 UI 偏好开关不能冒充系统已经接管。所有实机写入遵守 AGENTS 的专项隔离与授权限制；不得在此次独立数据目录测试中顺带改宿主。

## 8. 设置：我最后输入的值究竟保存了没有，生效了没有

实测组合问题：

- 在工具栏打开“双击激活”，随后仅打开参数设置，该选择就从 true 回到 false。
- 保存端口 11850→窗口继续保持打开→再改成 11851→点“应用”：实际保存值仍为 11850，窗口关闭。
- 应用请求报 `E_REVISION_STALE`：`expected revision 0, current 9`。普通用户没有手动处理 revision 的步骤，这个冲突在正常顺序中不应由用户承担。
- 错误后的主界面截图没有就近错误/恢复提示，主要操作区仍显示 Stopped。

应固定三类设置语义：原版规定即时生效的 UI 偏好；通过保存提交的配置草稿；保存后需运行重载或应用重启的设置。每类使用明确、一致的反馈，而不是每一页临时决定。

“应用”应处理当前最新草稿：校验→提交→更新 desired 状态→申请应用→等待权威结果。保存失败保留窗口和输入；应用失败保留恢复上下文，不因先关闭窗口而让输入与结果无法核对。取消尚未保存的草稿不得产生系统副作用；已经保存后的关闭/取消应把含义表达清楚。

复验核心路径：开窗口→改值→取消→重开；改值→保存→重开；保存→再改→应用；保存成功但应用失败→修改→再试；同一偏好从工具栏修改后打开设置及重开进程。不要把修改端口的验证当作全部设置都已通过。

## 9. 路由与 DNS：我切换策略之后，正在跑的是哪套规则

本轮未执行真实路由/DNS效果测试。前端必须把当前选择的路由方案、已保存规则与实际应用方案一致地呈现；更改后按原版时机生效，或明确展示待应用状态和操作入口。

正常路径应包括：正在使用节点 A→从状态栏切换路由/模式→看到生效确认→进入设置调整规则→保存→返回主界面→检查该规则对实际请求产生的效果。禁止只在列表上显示新的默认勾选，而运行时仍用旧规则且没有可见提示。

失败/不适用内核/规则编译错误应在原入口可见，保留旧可用方案。测试应包含真实生成配置和合成代理/直连请求，不能只核对 ruleMode 字符串。

## 10. 用完、隐藏和重开：后台是否继续运行，返回后是否还是刚才的状态

本轮新进程读回：4 个节点、2 个订阅、A1-renamed 的活动 ID、端口 11850、双击激活 false。4 个节点包含 Ctrl+C 意外产生的克隆；读回成功不表示这一副作用正确。最后未提交的 11851 没有保存。

托盘和窗口系统生命周期未验证，尤其不能把测试进程 teardown 当成用户点击托盘退出。

应固定的流程：按原版区分隐藏、关闭窗口和退出；隐藏时正确保留后台会话，再次打开读取同一实际状态；退出按项目所有权停止/释放本应用的会话并恢复自己的系统变更。托盘节点/路由菜单、主窗口和运行状态使用相同对象；第二次启动按原版实例规则唤回或处理冲突，不能偷偷创建第二个会话。

复验：运行→隐藏→托盘唤回→切节点→停止→退出→重开。再覆盖后台更新进行时隐藏、应用失败后退出、进程异常终止后的恢复。所有进程操作只能针对本项目管理的会话。

## 11. 内核更新与备份：这是为了完成前面的使用目标

本轮只结合已有截图和入口走查，未下载/安装/执行自身替换。

需要按用户目标分别验收“首次缺少所需内核→获取→返回并启动”“运行中更新内核→失败保留旧版/成功生效”“更新本应用→明确版本与结果”“备份→恢复→重开”。不能把检查、下载安装、准备外部替换和完成升级都称为检查更新，也不能把 helper 路径作为主要操作反馈。

内核安装必须和当前节点需要的内核关联，既有全量更新入口保持原版结构。备份/恢复需要在当前设置、订阅、节点和运行上下文下检查结果，不能只证明生成了一个 ZIP。

## 需要统一的流程规则

1. **操作对象一致**：每个动作在点击时确定目标 ID；主界面分组、设置窗口选择、鼠标焦点、默认节点、运行节点分别定义，不能混用。
2. **返回不破坏上下文**：更新、保存、测速、打开另一窗口不会无故重置分组、选择、偏好或视口；后续操作目标可解释。
3. **提交和生效一致**：草稿、已保存、待应用、实际生效各有清晰边界；系统副作用不能越过普通取消边界。
4. **反馈就近可见**：关键结果不能藏在横向状态栏末端。状态栏保留总体事实，操作本身提供可见成功/失败及恢复路径。
5. **一件事所有入口相同**：菜单、工具栏、右键、快捷键、双击和托盘调用同一个动作。输入框保留自己的编辑快捷键。
6. **任务允许正常交错**：切页、隐藏和修改其他配置时，已提交任务按固定策略继续/取消/拒绝；任务完成不能操作用户后来选中的另一个对象。
7. **以使用闭环验收**：每条包含首次使用、重复使用、失败再试、取消返回、后台完成和重开；只测日志或函数被调用不合格。

## 建议执行顺序与放行要求

优先处理会误操作和阻断正常使用的路径，保持冻结版布局及菜单结构：

| 顺序 | 一次修复的用户流程 | 此次问题/前置 | 必须检查的结果 |
|---|---|---|---|
| 1 | 切分组后编辑/删除/测速 | 隐藏选择、刷新丢分组 | 始终操作用户可解释的目标，无误改/误删 |
| 2 | 新增订阅并更新当前分组 | 分组不刷新、两套当前订阅、反馈不可见 | 新分组即时出现，只更新指定分组，结果就近可见 |
| 3 | 设置默认并切换实际节点 | toggle 语义、运行链路、运行状态 | 同一目标幂等，真实后端确认实际目标，失败可恢复 |
| 4 | 设置保存再编辑后应用 | 草稿丢失、普通路径 stale、偏好重置 | 最新值保存且申请正确版本，失败不丢输入 |
