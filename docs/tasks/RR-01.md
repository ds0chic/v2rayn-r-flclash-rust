# RR-01 — 受管核心根唯一事实来源：安装 == 运行

状态：`implemented`（Rust 侧安装→定位→子进程根传递全链已在本机真实 Windows 环境验证；未做 Flutter GUI 端到端下载→运行，故不写 `verified`）。

任务 ID：RR-01（P1，来源于 `docs/evidence/parity-recheck-2026-10-04/runtime.md` 的 RR-01 全节）。

本次唯一用户流程：普通启动 RC（不设 `V2RAYN_R_CORES_ROOT`/`V2RAYN_R_XRAY_BIN`，可用独立 `V2RAYN_R_DATA_DIR`）→ 更新 Xray/sing-box 下载并安装 → 应用节点时 net-host 必须从**与安装同一根**解析出刚下载的可执行文件并可启动它，而不是报 `core_not_found`，也不是默默运行开发树 `tools/cores` 里的旧版本。

前置任务及已验证证据：冻结 v2rayN 7.25.4 commit `7d6a967c18c697f28dc6917122ed3a4993fcf336`；开始应用 HEAD `d27eff0`。上游对照：`U/ServiceLib/ViewModels/CheckUpdateViewModel.cs:377` 安装到 `GetBinPath(core)`，`U/ServiceLib/Manager/CoreInfoManager.cs:32-47` 用相同 `GetBinPath`/core 候选 exe 定位——原版安装与运行共用同一目标路径；本轮修复让本项目恢复到该合同。FIX-12 的 `CoreInstallLayout` 语义与 PGP 验签不在本卡范围且未改动。

对应 feature / 模块：`crates/runtime/src/adapter.rs`（`CoreLocator`）、`crates/application/src/{engine.rs,net_host_client.rs}`、`crates/bridge_api/src/api/t16.rs`、`services/net_host`（复用 `CoreLocator`，无源码改动）。

## 修复合同与实现

1. **engine 的 cores 根是唯一事实来源**：`<engine.data_dir()>/cores`，`V2RAYN_R_CORES_DIR` 覆盖。新增 `application::engine::managed_cores_root(data_dir)` 与 `AppEngine::cores_root()` 作为唯一定义；`t16::cores_root()` 改为委托 `engine().cores_root()`。
2. **跨进程传递**：`NetHostClient` 新增 `cores_root` 字段与 `with_cores_root`/`set_cores_root`/`cores_root`；`AppEngine::open` 用该根构造生产客户端；`launch_net_host` 经 `apply_launch_env` 在受管 net_host 子进程环境显式设置 `V2RAYN_R_CORES_ROOT`（进程已有的显式同名变量优先）。不要求用户设置任何环境变量。
3. **net_host 定位优先级**：`CoreLocator::from_env` 将显式 `V2RAYN_R_CORES_ROOT` 置于首位，且一旦存在即为**唯一**根，禁用 `tools/cores` 开发后备，保证开发树在生产路径不掩盖；无显式根时默认 `default_managed_cores_root()`（`V2RAYN_R_DATA_DIR` 或 `%LOCALAPPDATA%/v2rayn-r/data/cores`）与 `AppEngine::default_data_dir()/cores` 对齐，`tools/cores` 仅作最低优先级开发后备。
4. **同一 CoreInstallLayout**：安装（`update_service::install_core_from_dir`）与运行（`CoreLocator`）均经 `CoreInstallLayout` 构造 `<root>/<dir>/<version>/<exe>`，无分叉。
5. 不改 FIX-12 布局语义与 PGP 验签；不改 `frb_generated`、Dart、net_host 源码。

输入/输出/错误/取消/权限/持久化及生效语义：
- 输入：engine data dir 或 `V2RAYN_R_CORES_DIR`；可选进程级 `V2RAYN_R_CORES_ROOT`（测试/开发覆盖）。
- 输出：net_host 解析到安装根下的 exe；`AppEngine::cores_root()` 与 `t16` 安装根一致。
- 错误：显式根下找不到 exe 时仍报 `error.core_not_found`，不回退开发树。
- 权限：仅本机文件与子进程环境；不监听端口、不写系统代理/TUN/注册表。
- 持久化：安装目录与 manifest 不变。
- 生效：下一次受管 net_host 启动即携带正确根。
