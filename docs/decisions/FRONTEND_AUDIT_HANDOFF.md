**执行模型必须遵守的顺序**

1. 在任务卡写清产品、冻结工作树/子模块、目标仓库与本次唯一SB-J/VN-J流程。SteamBox的专属冻结台账由S00/S02完成，不使用v2rayN台账作为替代。
2. 从该流程入口展开所有页面、按钮、菜单、字段、焦点、系统/原生弹窗和后台后继；列元素ID、action/field/route、目标ID、权威状态所有者和失败路径。
3. 同一action的点击、双击、键盘、托盘、URI复用同一实现。单击选择与业务启动分开，request ID去重，读query latest-wins，写operation有提交点/有限deadline/取消/补偿/未知核对。
4. 先修整条状态链，再接控件。跨账号/组/revision/进程结果不得污染新投影；已提交旧操作仍在原上下文结算。保存中再编辑不能被旧回执清除。
5. 走UI→Rust→持久化→返回→重开→实际配置/文件/native/platform效果；普通用例使用真实实现，mock只做故障注入。外部平台无法实测就写未验证。
6. 跑正常/重复/失败/取消/跨页/重开/交错变体，并记录操作→第一反馈、UI/raster慢帧与资源峰值。Debug不能作为最终性能成绩。
7. 更新对应原任务卡和证据，汇报实际命令及结果、文件、剩余前置。未解析元素、占位动作、假进度、吞错、局部按钮通过但后继失配，均不放行。

**必须修正的用户体验断点**

- SteamBox：账号卡双击重复入口、登录配置写入冒充已登录、Web/native身份不符仍启动、取消编辑仍改共享数据/图片、成就保存失败进入重置、下载通知倒计时并未等待、不同功能按AppId共用进程记录，以及旧SDK测速结果写新游戏。
- v2rayN：当前组与导入/更新目标错位、窗口写入未刷新主投影、保存→应用使用旧revision、设置值被测速常量/启动load覆盖、空目标扩大为全库、跨页过滤不可见、停止未确认与job不可及时定位。

以上为源码静态发现或需覆盖的风险，实际症状未实测；方案明确修正目标，不复制伪成功/重复副作用。当前未运行真实窗口、代理、Steam、SDK、平台或性能测试，不能据本轮文档宣布“已无卡顿”。
