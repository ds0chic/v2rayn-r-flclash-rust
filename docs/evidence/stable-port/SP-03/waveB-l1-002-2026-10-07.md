## 1. Actual gap (investigated, not assumed)

Upstream `CertPemManager.ParsePemChain` returns the full block list, and the
Rust port (`config_codegen::util::parse_pem_chain`) already did the same. Both
main TLS emission paths already emitted the whole chain in order:

- Xray `tlsSettings.certificates[]` (one entry per block, `usage: verify`);
- sing-box `tls.certificate[]` (full block array).

The real defects were:

1. **Fail-open on malformed chains.** `parse_pem_chain` is documented
   best-effort: a non-empty `cert` that parses to zero blocks was silently
   dropped, and generation fell through to `cert_sha` or to plain system
   roots. A broken pasted chain therefore produced a *working-looking*
   config verified against the wrong trust — fail-open.
2. **Leaf-only Shadowsocks plugin path** (`certs.first()` → `certRaw=`),
   mirroring upstream `SingboxOutboundService.cs:160` (`certs.First()`).
   `certRaw` is a single-cert plugin option, so leaf-only there is upstream
   parity, not a bug to "fix" by inventing a multi-cert encoding. Locked in
   by test + documented here.

Storage needed no change: `SecurityParams.cert` (`crates/domain`) and the
`Cert`/`CertSha` SQLite columns (`application::store_repo`) already carry the
raw string verbatim; `application::codegen::to_codegen_profile` passes it
through untouched. Proven by the reopen roundtrip test below.

## 2. Changed files (minimal set; no `engine.rs`, no bridge/ipc/services/FRB)

- `crates/config_codegen/src/util.rs` (added): `validate_pem_chain` —
  strict fail-closed counterpart of `parse_pem_chain`. Blank input = "no
  material" (Ok); otherwise rejects unterminated blocks, empty bodies,
  non-base64 bodies, bad `=` padding, and zero-block input with structured
  `CodegenError { code: "invalid_certificate_chain",
  field_path: "profile.cert" }`. CRLF normalized like upstream.
- `crates/config_codegen/src/xray/outbound.rs` (+7 lines): gate at the top
  of per-node `fill_bound_stream_settings` (covers group children, which flow
  through `build_proxy_outbound`): `if stream_security == "tls" {
  validate_pem_chain(&cert)? }`.
- `crates/config_codegen/src/singbox/outbound.rs` (+5 lines): same gate at
  the top of per-node `fill_outbound` (covers the main TLS block and the
  Shadowsocks plugin path, incl. group children).
- `crates/config_codegen/tests/cert_chain.rs` (new, 7 tests): chain order
  (xray + sing-box), leaf-only, empty-cert, 6 malformed cases x both
  generators with structured-error assertions, reality scoping, SS plugin
  leaf parity.
- `crates/application/tests/cert_chain_roundtrip.rs` (new, 2 tests):
  save → drop → independent reopen keeps the chain byte-for-byte with leaf
  before CA; `to_codegen_profile` carries it verbatim.
- Domain (`crates/domain/**`): intentionally unchanged — no validation
  added to `Profile::validate`/`is_valid`, so editor-draft and import
  contracts are unaffected; enforcement sits at the generation boundary
  where the material is consumed.
