输入、输出、错误、取消、权限、持久化及生效语义：
- 输入：`update_subscriptions(subIds, via_proxy)`；`sub_ids` 空表示全部启用订阅。Rust 逐组下载解析，候选优先，失败保留旧节点。
- 输出：每组的 `updated/preserved_empty/preserved_error/skipped/cancelled/failed`、真实 `added`/`removed`、`code`/`message` 组成 `SubUpdateReport`；`report_to_json` 暴露同样字段。
- 终态获取：同一 job id 的 report 由 `subscriptions_updated` 事件携带；同时缓存到进程级 `SUB_REPORTS` 并以 `subs.report:<json>` 前缀停驻在该 job 的 `stage_key`，使现有 `job_view` 能在同一 job id 上取回完整 report（无需改 FRB 生成物）。
- 错误：单组失败只影响该组行；请求级错误（如 `E_PROXY_UNAVAILABLE`）仍按 FIX-09 语义返回。
- 取消：`report.cancelled()` 决定 job 终态；被取消 run 绝不返回成功（FIX-09 语义不变）。
- 权限/平台：仅本机 UI + FRB/Rust/SQLite；不监听端口、不写宿主代理/TUN。
- 持久化：`replace_sub_profiles` 原子替换；`added/removed` 为真实计数。
- 生效：Dart 用 report 逐组构造 `SubUpdateEntryDto`；`_summarize` 汇总“成功/跳过/保留/失败”，`success` 只计 `updated`，`added` 取真实值。
