**前端交互契约：按完整使用流程固定行为**

日期：2026-10-02。这是对冻结方案的补充规格与审阅规则，应用源码未由本次审阅修改。`outputs/`与`work/`保持只读。此文件固定应实现的行为；没有运行真实窗口、代理、Steam、系统接入或性能测试，不声明实现已通过。

**1. 使用方式与范围隔离**

先按目标产品选择流程台账，再应用本文公共规则。SteamBox范围仅网络加速、账号切换、库存游戏、挂卡；Authenticator、ASF、GameTools删除，不能因交互审阅重新加回。当前仓库的v2rayN Flutter实现是另一套产品，以冻结v2rayN菜单/表格/设置及上游动作语义为准。不得互相套导航、设置提交方式或快捷键。

本文中的“固定”指执行模型不得逐页自行决定相同动作的含义。存在源依据冲突时先登记一项决策和实际原版结果，再修改规格与所有入口；不能边写页面边随意换行为。台账状态只用`identified / implemented / verified / preserved_only / blocked / not_applicable`；规则已写清楚不等于功能verified。

完整闭环必须包含用户目标、入口、前置、动作顺序、状态所有者、每步反馈、跨页影响、取消/失败、再次进入和真实后端效果。局部按钮可点击、widget测试通过、Rust编译通过，不能代替闭环。

**2. 唯一状态模型与反馈词义**

| 状态 | 事实来源 | 用户应看到 | 禁止表现 |
|---|---|---|---|
| 本地输入/选择 | Flutter草稿与焦点 | 输入、选中、筛选结果立即响应 | 把选中当已运行、未提交输入覆盖保存值 |
| 正在提交 | Flutter已发request，尚未收到权威回执 | 下一帧显示按下/提交反馈 | 把本地派发当Rust已经接受 |
| 命令已接受 | Rust返回request/operation标识 | 必要时“正在…”；目标明确 | 仅pointer down就提示成功 |
| 已保存 | 持久化事务确认 | “已保存”；另说明待生效条件 | 把SQLite/文件保存当系统/运行效果完成 |
| 正在应用 | Rust运行管理与任务事件 | 进行状态，相关操作有一致busy边界 | 开关先显示稳定成功但服务尚未就绪 |
| 已生效/已完成 | applied revision、真实探活或领域结果 | 对应目标和效果准确，完成状态持续可查 | 内核/Steam/SDK错误仍显示已切换 |
| 失败/部分完成 | 结构化错误与已完成阶段 | 保留上下文与草稿，指出未完成效果、恢复/重试入口 | 关闭弹窗、清空列表或toast后无从恢复 |
| 结果未知 | 外部写超时或进程断连 | “结果待确认”；先查询 | 自动重试非幂等写、把超时当必然失败 |
| 已取消 | Rust确认任务停止/未提交 | “已取消”；已发生效果如实显示 | 只停页面等待就说外部操作已撤销 |

operation ID用于追踪同一动作。request ID、query ID、revision、process epoch、account epoch分别解决请求关联、搜索过期、配置收敛、重启和账号变化，不能用一个busy布尔替代全部机制。

纯导航、焦点、展开和本地选择在Flutter内完成，不要求Rust回执；只读查询不逐次写operation journal。需要恢复的领域副作用由Rust登记operation，并回传request ID。按钮的本地按下反馈与业务接受严格区分。

收到事件序列缺口后重取权威快照；权威快照到达前保留最后可靠数据并说明连接状态，不能全部清空造成误操作。每个界面投影带相同实体ID和版本，不允许表格、托盘、标题、详情各维护一份当前目标。

快照携带epoch和事件watermark，后续订阅从watermark之后无缝接续；服务提供有界补发或明确resync_required，不能静默漏事件。恢复/远端赋值带origin，不能触发用户提交回路；首次绑定不执行开关、保存或启动动作。

统一反馈模板如下，替换为用户可识别目标名，不能展示内部ID/字段/error_key；密码/会话目标不进入提示内容。数字进度只用真实数量，未测的延迟/丢包/配额以“未测量/暂不可用”显示，不用0冒充有效值。

| 条件 | 固定文案与呈现 |
|---|---|
| 派发无回执 | 原触发处“正在提交…”；导航保持可用 |
| 长任务已接受 | “正在{阶段}：{目标}”，出现实际等待对象；无总量则无百分比 |
| 纯存储成功且立即UI效果已核实 | “已保存”；短反馈不抢焦点 |
| 下次启动/运行生效 | “已保存，下次{启动应用/启动Steam/启动加速}生效”；字段附近保留条件 |
| 保存成功而apply失败 | “已保存，应用失败，仍在使用上一配置”；持久提示+相关重试/恢复入口 |
| 请求取消 | “正在取消…”；按钮不反复派发，不提前改完成计数 |
| 取消确认 | “已取消”，另列已发生的部分效果；草稿关闭不造任务取消toast |
| 外部写超时且效果不明 | “结果待确认”；提供核对，自动非幂等重试禁用 |
| 登录挑战 | “需要{验证码/邮箱验证码/家长PIN}”；错误留该步，聚焦正确输入 |
| 身份不符 | 说明客户端与Web账号不一致并给切换/重新登录入口；启动禁用有原因 |
| 失败/部分完成 | 原上下文显示原因、已完成项、未完成项和可用恢复；不自动关窗口 |
| 查询离线/失败 | “刷新失败，显示上次数据”与时间；不清空旧列表 |
| 查询确认有效为空 | 说明当前筛选/账户/排除范围；空数据不等于后台任务全部完成 |

普通成功/复制toast默认2秒、同一operation最多一次；错误持续于目标区域直到确认解决或用户关闭，关键待确认/待应用状态关闭toast后仍可查。通知不移焦点、不切页、不盖住正在输入的模态；原必要权限/登录/破坏性确认单独处理。

**3. 统一交互类型规则：所有元素必须映射到一条**

| 规则ID | 元素类型 | 固定行为、反馈、焦点与副作用 |
|---|---|---|
| P00 | 布局容器/边线/静态装饰 | 只负责原布局/命中区域；不触发业务，不遮挡输入，不参与Tab，不制造常驻动画 |
| P01 | 文本/状态标签/徽标 | 读权威投影；可复制文本遵循焦点选择；原始错误键/开发任务ID不直接展示；信息不能只靠颜色 |
| P02 | 图像/头像/封面/图标 | 可见区异步加载与解码，固定占位防布局跳；失败有同尺寸fallback；静态图像不暗示可点击 |
| P03 | 普通命令按钮 | pointer/键盘只调用同一action；按下反馈即时；提交后按冲突域single-flight；成功/失败回原上下文；不全页禁用 |
| P04 | 运行启停按钮/开关 | 请求目标状态由Rust收敛；未确认前显示正在启动/停止；多次相同目标幂等；反向操作排队/取消按领域规定 |
| P05 | 刷新/重试 | 保留已显示内容、滚动、筛选、选择；只读同查询替换旧请求；副作用重试先按原结果核对；成功合并差量，失败不变空列表 |
| P06 | 即时设置开关 | 只用于源确认即时语义字段；立即反馈输入并请求持久化/效果；失败恢复最近确认值或显示待处理；文案区分存储与效果 |
| P07 | 草稿表单开关/输入 | 改当前draft，不写系统或启动任务；取消丢弃草稿；保存失败保留输入；不能套在原即时设置上 |
| P08 | 文本/密码/数字输入 | 保留输入法组合与选区；键入不调用阻塞I/O；失焦/提交按字段规则校验，错误就地；密码不进日志或持久UI状态 |
| P09 | 搜索框 | 按源声明on_change或on_submit；实时查询最多100ms合并，组合输入完成后才查询；原Enter提交语义保留；旧query不能回写，不启动业务动作 |
| P10 | 下拉/单选/滑块/颜色/日期 | 值变化按字段提交策略，选项有稳定值；滑动每帧仅预览、提交合并，不能同步fsync；依赖禁用理由可理解 |
| P11 | 根导航/页内标签 | 同页点击幂等；切页不停止任务；保存页面的筛选/滚动/选择；根切换与子后退不同；没有伪成功和不必要loading |
| P12 | 设置页锚点 | SteamBox保留同一长页滚动与标签联动；程序滚动有origin标记防递归；不生成新路由或重复保存 |
| P13 | 列表/网格/表格行 | stable ID键控，虚拟化；更新保持可见锚点，不重建全列表；明确focused/anchor/selected三者；不在重绘中提交动作 |
| P14 | 行点击/双击 | 单击仅选中；双击仅对应源定义动作；只绑定一次，不按钮冒泡再提交；重复动作是否幂等由action契约决定 |
| P15 | 批量选择/全选 | 目标集合在点击时冻结并可见；“全选”范围明确；过滤/换组/换账号不携带不可见旧目标；全选三态按本视图集合计算 |
| P16 | 右键/上下文菜单 | 在正确目标上打开，菜单动作和按钮/键盘共用action；右键不激活业务；空白区域无行目标；目标失效则关闭/禁用 |
| P17 | 拖拽/上移/排序 | 明确可用条件；拖拽视觉预览与后端持久化分离；失败恢复；筛选/列排序不偷偷改全量手工顺序 |
| P18 | 子页/弹窗/返回 | 打开保存触发元素焦点；关闭还原同一元素或最近可用替代；Esc只关最上层可取消弹窗；未提交草稿按规定处理 |
| P19 | 文件/目录/外部链接选择 | picker取消不报错、不清旧值；返回核对当前上下文；打开外部应用只反馈请求已交付，不假定其业务成功 |
| P20 | 确认/删除/重置 | 仅原必要破坏性动作确认，文案列目标和影响；确认后的selection changes不改变目标；取消零副作用 |
| P21 | 进度/加载/图表 | 真实阶段/字节/总数；未知总量用不定进度；历史内容不断闪空；图表/统计限频，非可见停止绘制但任务继续 |
| P22 | 日志/通知/错误 | 有界差量列表；滚离底部不抢滚动；同operation重复错误合并；关键失败有持久状态，toast不是唯一凭证 |
| P23 | 登录/验证码挑战 | 提交后保留当前挑战状态；错误回该步；不反复弹窗抢焦点；输入2FA/邮箱码与OTP管理分开；请求/账号epoch核对 |
| P24 | 标题栏/窗口/托盘 | 原生拖动/缩放/系统按钮命中；最小化/关闭/隐藏/退出各自一致；单实例恢复同一权威状态，不能重启后台任务 |
| P25 | 超链接式说明/工具提示 | 描述动作/禁用原因；不承载仅悬停才能完成的必要操作；可访问文本和键盘焦点按原控件含义提供 |

对应源控件可具有多个规则：例如账号卡容器P13+P14、切换按钮P03+动作single-flight、当前账号徽标P01。控件未映射、规则冲突、action未解析、仅fallback日志/echo的项均不能通过门禁。图标按钮必须有可访问名称；disabled状态仍能说明原因，不要求用户猜。

**4. 单次动作、并发和取消必须固定**

- 普通按钮不统一加任意500ms/2s防抖。重复命令按operation/目标状态去重；只有搜索、滑块/窗口resize等高频输入做短合并。
- 读请求latest-wins，单实体写single-flight，全局账户切换排他，网络apply按desired revision串行收敛。来源无论按钮、双击、托盘、URI还是快捷键都复用同一领域命令。
- 可恢复副作用以request ID去重：同request的重复投递返回原operation，不能再执行一次；回执丢失先按request查询。幂等记录按journal生命周期保留，不用短UI防抖代替。纯读查询不用为此写持久化journal。
- 列表刷新与运行日志不会锁住导航；Cloud写/成就提交/账号切换等只锁其冲突域，并展示目标。取消按钮只是“请求取消”，收到确认后更新。
- 页面关闭可取消页面读请求和订阅；不能取消已经授权启动的加速/AFK/挂卡任务。显式退出按应用生命周期停止自己拥有的任务并等待清理。
- 超时针对具体阶段，不用一个10秒超时取消所有动作。交互立即反馈；外部登录、下载或系统权限可以更久，但阶段和可恢复入口保持可见。

每个action在实现前填入有限阶段deadline、可取消阶段/副作用提交点、失败补偿及unknown结果的核对来源。超过deadline进入失败/待确认/等待用户中对应状态；不让spinner永久运行。登录挑战等待用户与执行请求超时分开，返回可用；不能按统一截止强制重试写操作。

**5. 选择、焦点、返回和刷新不别扭的确定规则**

维护`focusedId / anchorId / selectedIds / viewKey / scrollAnchor`。同view数据更新保留仍存在目标；连续Shift从固定anchor计算，不从selected.last计算。删除目标从集合剔除并选最近可用焦点；排序后按ID找位置，不按旧index引用。

换账号一定清空旧账号selection；换订阅组/平台/作用域清空不属于新view的selection；搜索过滤默认仅操作当前可见集合，若产品原版支持跨过滤选择则必须有明确数量/范围提示并单独固定。不能保留隐形selection再对它执行删除/测速/云操作。

刷新保持筛选、布局、手工/字段排序、滚动锚点和有效selection；内容未确认完整时不推导“全部下载完成”“全部卡已掉完”。先打开详情再返回恢复原view，不因异步旧结果跳回顶部。账号切换是上下文变化，允许重取新库，但明确loading目标账号，不把旧库标成新用户所有。

快捷键按产品原版及焦点scope固定。文本框优先原生编辑键；菜单/表格scope才执行业务键。SteamBox没有源码证据的应用级Ctrl+F/F5等不凭习惯新增；v2rayN必须按其上游含义，不把Ctrl+C复制实现成克隆。Enter与双击也不是全产品通用“开关”。

**6. 表单提交边界：不用统一保存按钮改变原体验**

每个字段声明`preview_only / immediate / commit_on_blur / dialog_commit / restart_required / next_run`之一或明确组合，另声明失败恢复策略。禁止执行模型逐控件自行选。

SteamBox设置长页的原即时订阅语义按字段保留；GPU/插件启用等标重启要求；代理设置的存储revision与网络applied效果另显示。库元数据编辑保留应用overlay保存与应用到Steam两阶段。v2rayN设置窗口的草稿/保存/应用/取消要按该原版语义核实，不能直接借用SteamBox自动保存。

有“保存”和“应用”两个动作的表单：应用先校验最新草稿并完成需要的持久化，再申请应用；不能保存后再编辑却应用旧值。dirty与saved-but-not-applied是两个标记。保存失败保留输入，应用失败保持已保存和未生效事实，不整页reset。失败关闭窗口之前必须有明确可恢复结果，不能只toast。

提交保存时冻结draft revision及字段集合，保存进行中允许不冲突输入继续编辑。旧save回执只清理该revision已提交且未再次改动的dirty字段，不能覆盖新草稿；下一次应用提交最新有效草稿。即时设置快速连改也带field revision，过期失败不得回滚更新的输入；权威失败与尚待处理的最新值分别显示。

即时预览可逆属性（颜色/材质等）与不可逆系统动作分离。带取消按钮的草稿窗口，任何自启/代理/文件变更不得偷偷提前执行；若原版确认是即时提交，必须明确取消仅关闭、不声称撤销，并通过其正确回退策略验收。

**7. 反馈和可感知流畅度预算**

实施约束：UI isolate不做同步磁盘/网络/进程等待或大文件解析；Rust阻塞工作进入有界worker队列，长任务不持有阻塞其他查询的全局锁。10k表格/库采用分页与差量，日志按有界批次更新；原始业务事件完整处理，绘制事件可合并。只重建受影响行/字段，避免每次统计刷新重建根窗口。图片按显示尺寸异步解码、限制缓存；隐藏页释放绘制订阅和临时资源，不停业务owner。切页先显示可交互壳和可靠缓存，再读取外部数据；loading不遮掉整页。上述约束必须在并发真实流程中测量，不能靠代码风格宣称达标。

| 环节 | 固定目标与失败判定 |
|---|---|
| 按下/键入/hover | 下一可用帧显示反馈；测试点击至第一反馈p95≤50ms、p99≤100ms |
| 普通本地反馈 | ≤100ms；时间超出则进入进行态，不能像点击无效 |
| cached切页 | p95≤150ms；UI先切视图并保持相关状态，外部I/O不阻塞根导航 |
| 搜索 | 源定义实时查询的组合输入结束后合并≤100ms；提交式从Enter开始测量；10k数据首屏结果p95≤120ms不含用户打字间隔，另记录总等待 |
| 长动作 | 100ms内可见提交反馈；收到Rust回执才称已接受；超过300ms有清楚进行状态；超过2s有阶段/等待对象及可用取消/返回说明 |
| 60Hz渲染 | UI/raster分别记录；p95各≤8ms为目标，99%以上实际帧≤16.7ms；120Hz预算8.3ms单列 |
| 后台压力 | 同时日志/扫描/测速或挂卡时，输入/菜单/滚动仍达上述门槛；平均FPS掩盖卡顿不能通过 |
| 返回/重开 | 同scope筛选/滚动/布局/草稿按策略一致；首次点击可用，不需要“多点一次”恢复 |

以上是验收目标，当前未实测，不能写“已无卡顿”。测量必须包含输入→Dart→FRB/Rust→返回→可见提交的时间分段，也记录OS原生picker/UAC阶段；只测controller函数耗时不够。运行用合成数据、已探测可用≥11808端口，禁止10808和宿主代理修改。

Profile/Release分别用于定位/最终用户指标，Debug不作性能成绩；滚动时同时看UI与raster慢帧、资源峰值和连续卡顿。Flutter官方资料说明两线程任一超预算会影响流畅，推荐用性能视图逐帧定位。[Flutter帧性能分析](https://docs.flutter.dev/perf/ui-performance)、[性能实践](https://docs.flutter.dev/perf/best-practices)

**8. 整体审计路径与门禁**

每条使用路径至少有：首次使用、正常重复、失败再试、取消/离开/返回、跨页后台完成、重开、与另一任务交错。路径包含所有目标控件的点击、键盘、selection和可见反馈，而不是孤立截图。

| 路径类型 | 必查的不变量 |
|---|---|
| 初始化→选择→执行→返回 | 页面可交互/初始值正确，selection不暗示已运行，返回不丢上下文 |
| 设置→保存→再编辑→应用 | 最新草稿与saved/desired/applied一致，不应用旧值 |
| 任务运行→切页→修改上下文 | 正确继续/停止/拒绝；旧epoch结果不回写，新view不被旧toast误导 |
| 查询→过滤→刷新→批量动作 | 目标集合始终可解释，group/filter/sort不在刷新后丢失 |
| 外部请求失败→重试 | 无伪成功、无空结果冒充完成、未知写结果先核实 |
| 隐藏→第二启动→唤回→退出 | 同一operation状态，后台不重复创建，关闭语义正确 |

放行要求：每个保留元素有稳定ID、源证据、有效规则和action/字段/route；每个动作至少一个完整流程用例；每个跨模块冲突有测试；无占位/echo/吞错回调；隐藏插件排除有效；所有实际结果状态诚实。原生托盘/权限/窗口不能只靠Flutter集成测试覆盖，官方集成测试工具的边界需补平台验收。[Flutter集成测试边界](https://docs.flutter.dev/cookbook/testing/integration/introduction)
