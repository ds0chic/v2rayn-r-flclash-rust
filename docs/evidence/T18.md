## 2. 性能结果

### 2.1 冷启动（release，rows=1000，n=10）

| 指标 | p50 | p95 |
|---|---|---|
| 进程启动 → 首帧标记（含进程创建/DLL/引擎初始化） | **1202.01 ms** | **1272.42 ms** |
| 进程内 `main()` → 首帧 | 74.57 ms | 111.84 ms |

样本 10/10 写出标记，无失败。对照 §16 “冷启动 p95 ≤ 2s”目标：本机口径远低于目标。
注意：迭代 1 之后 OS 文件缓存变热，严格“冷缓存”未建立，方法学限制见 §6。

### 2.2 表格滚动帧时间（60Hz，预算 16.7ms，n=599）

| 行数 | build p50 | build p95 | raster p50 | raster p95 | 合计 p50 | 合计 p95 | 超预算帧 | 掉帧率 |
|---|---|---|---|---|---|---|---|---|
| 10,000 | 14.25 ms | 21.78 ms | 2.88 ms | 3.28 ms | 17.00 ms | 24.59 ms | 333 | 55.6% |
| 50,000（探针） | 25.88 ms | 36.92 ms | 3.00 ms | 3.40 ms | 28.70 ms | 39.90 ms | 599 | 100% |

解读：**raster 始终远低于 16.7ms**；超预算全部来自 build，且与行数正相关——脚本化 `jumpTo`
强制整表重建是主因（与 T01 S1 记录一致）。该数据是上界探针，不能据此判定真实拖拽滚动不达标；
未做真实拖拽手势测量（见 §6）。

### 2.3 内存（release，WorkingSet64，每档 23 样本）

| 场景 | p50 | max |
|---|---|---|
| 空载（rows=0） | 146.49 MB | 158.20 MB |
| 10k 行 | 178.76 MB | 190.75 MB |

10k 行相对空载 +约 32MB；未见采样窗口内单调增长（短窗口，不作长期结论）。

### 2.4 日志吞吐（Rust 环形缓冲）

- 注入 100,000 行：保留 10,000、丢弃 90,000（`retained + dropped == injected`），耗时 11.5ms，**0.115 µs/行**。
- 字节上限：注入 2,000×64KiB，保留按 10MiB 上限截断，丢弃 120,659,871 字节。
- 结论：环形缓冲有界且吞吐充足。**UI 侧“日志洪峰帧时间”未单独测量**（见 §6）。

## 3. 稳定性结果

### 3.1 会话循环 20×（apply/stop）

- 成功：**20/20**；每次 apply 到达 Running、端口 owner==xray pid、stop 后进程消失且端口释放。
- 循环内自管 Xray 残留：0；自管 net_host 未退出：0；循环后自有 PID 存活：0；端口占用：false。
- 单次 apply→stop 耗时约 1.28–1.63s。
- 说明：泄漏统计只针对本脚本启动的 PID；宿主自有的 `xray.exe`（用户 v2rayN 实例）不计入、不被终止。

### 3.2 应用重开 10×（Rust 引擎，同一数据目录）

- `guiNConfig.json` SHA-256 全程一致：`e9b2b7cb09e75279abd8a61c30cdf6cd70380f50b715571c4e6d06d170c31191`。
- settings revision 稳定（=1）、profile 数稳定（=1）、`drift=0`。
- 限制：为引擎级 10 次 open，不是 GUI 10 次启动（见 §6）。

### 3.3 异常路径（既有 T03 故障矩阵复跑）

| 用例 | 结果 |
|---|---|
| smoke-config（xray -test 校验生成配置） | passed |
| a 正常闭环 | passed |
| b 端口占用（E_PORT_CONFLICT） | passed |
| c 客户端强杀（租约回收杀 core） | passed |
| d net-host 强杀（Job 杀 core + 重启恢复 journal） | passed（修复后，见 §4） |
| e core 秒退（结构化 E_INTERNAL，无假 Running） | passed |

写失败路径（Rust 测试）：`T18_IO_ERROR {"code":"E_INTERNAL"}`、`{"phase":"settings_save","code":"E_INTERNAL","old_value_kept":true}`。

### 3.4 样本量与限制（明确不是 24h soak）

- 会话循环 20 次、重开 10 次、运行会话 15s 采样、冷启动 10 次、滚动各 599 帧。
- **未做** 24 小时持续运行；因此只能给“短时无泄漏趋势/无漂移”的结论，不能外推为长期稳定。

## 4. 缺陷修复（前后对比）

### T18-F01 设置保存失败不回滚内存（`crates/application/src/engine.rs`）

- 修复前：写盘失败后内存为新值、文件仍旧值。测试失败：`left: Some("trace") != right: Some("debug")`。
- 修复：保存前快照，写盘失败回滚 settings/revision/group_revisions。
- 修复后：`t18_stability` 5/5 通过，`old_value_kept=true`。

### T18-F02 已退出进程被误判为存活（`crates/runtime/src/identity.rs`）

- 修复前：`t03_faults.ps1` 的 `d-net-host-kill` 连续 2 次失败，日志 `cleaned=false`，journal 停在 `applied`。
- 根因：`GetProcessTimes` 的退出时间未检查；进程内核对象在句柄/Job 关闭前仍可查创建时间。
- 修复：exit FILETIME≠0 视为已退出，`process_creation_time_ms` 返回 `None`；新增单测覆盖。
- 修复后：`cleaned=true`，6/6 故障用例通过。
