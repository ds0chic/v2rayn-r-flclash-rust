## 个人抽查复核记录（HEAD = 29221bf）

本人（Gemini 3.8 Flash）直接针对源码进行抽查验证，重点核对以下 8 项子代理发现：

1. **复核 10808 端口保护逻辑**：
   - 查看 `crates/config_codegen/src/util.rs:257-280`，确认 `reserved_port_error` 明确对 `settings.inbound.local_port == 10808` 以及 `state_port`/`state_port2` 抛出 `CodegenError::reserved_port`，有效切断生成流。
2. **复核 Flutter 取消订阅假状态 (FINDING-01)**：
   - 查看 `apps/desktop/lib/features/subs/subs_controller.dart:180-187`：
     ```dart
     void cancel() {
       final jobId = state.lastJobId;
       if (jobId == null) return;
       ref.read(bridgePortProvider).jobView(jobId);
       state = state.copyWith(
         status: const SubStatus(kind: 'info', message: '已请求取消'),
       );
     }
     ```
     查看 `apps/desktop/lib/bridge/bridge_port.dart:85-100`，`BridgePort` 确实**完全没有** `cancelJob` 方法声明，尽管底层 FRB 生成的 `crates/bridge_api/src/api/engine.rs:703` 提供了 `cancel_job`。UI 触发的“取消”纯属假象。
3. **复核订阅替换非事务原子性 (FINDING-02)**：
   - 查看 `crates/application/src/engine.rs:809-856`：
     函数 `replace_sub_profiles` 中直接对 `repo.query`、循环执行 `repo.remove`、然后循环执行 `repo.upsert`。底层 `store_repo.rs` 每次都是独立的单条 SQL 执行，没有 `BEGIN TRANSACTION / COMMIT` 保护。崩溃必然导致数据被全部删除后无法写入新节点。
4. **复核 T12a Inbound 字段 null 语义丢失 (FINDING-03)**：
   - 查看 `crates/domain/src/entities.rs:354-355`：
     `pub user: String` 与 `pub pass: String` 为非 `Option` 类型。
     对比 `compat/fields.settings.yaml:1626-1628`，字段规范标明为 `default: null`，`null_handling: 缺省null`。当前直接序列化为空字符串 `""`，丢失了 `null` 区分。
5. **复核 T12a SimpleDNSItem 加载默认值不一致 (FINDING-04)**：
   - 查看 `crates/domain/src/settings.rs:1016-1036` (`apply_load_defaults`)：
     仅处理了 `block_aaaa_query`, `fake_ip_range`, `global_fake_ip`, `bootstrap_dns` 等字段，确实**遗漏**了 `fake_ip`、`direct_dns` 等字段。当反序列化空 JSON 时 `fake_ip` 留在 `None`，而 `AppSettings::default()` 则为 `Some(false)`。
6. **复核全局 ENGINE 单例在测试中重试打补丁 (FINDING-05)**：
   - 查看 `crates/bridge_api/src/api/engine.rs:925-947`：
     注释明文记载 `"The engine is process-global and other tests bump the revision concurrently; re-read until the save lands so the stale-rejection below tests the contract instead of a race."`，并在循环中进行了最多 10 次重试。
7. **复核 T09.md 违反“严禁 verified”红线 (FINDING-06)**：
   - 查看 `docs/evidence/T09.md:3`：
     明确写着 `状态：implemented + verified（Rust 侧）`。与 AGENTS.md 及 T00 约定的台账状态规范冲突。
8. **复核订阅编辑窗口中的死字段 (FINDING-07)**：
   - 查看 `crates/application/src/subs.rs:377`：
     `convert_target` 字段在代码中唯一的用途仅仅是 `if item.convert_target.as_deref().unwrap_or("").is_empty()` 时决定是否追加 `more_url`。未调用任何远端转换服务，`PrevProfile` / `NextProfile` / `PreSocksPort` 同样存入后在核心生成阶段完全无消费。

## 与执行方自述不一致之处

1. **T09 事务性自述不一致**：
   - 执行方声称“成功按 subid 先删后写，保证原子性”；反证显示代码层无事务，是多条单独 SQL，存在中途崩溃丢失数据的窗口期。
2. **T09 取消机制自述不一致**：
   - 执行方在 Rust 侧完整实现了取消令牌传递，但宣称“UI 接线完成”，实际 Flutter 界面上的取消按钮仅仅触发了只读状态查询，根本没有将取消请求发送给 Rust 后端。
3. **T12a 180 字段全覆盖自述不一致**：
   - 执行方声称“180 字段 DTO 与默认值全面对齐”，但 `Inbound` 的用户密码丢失了 null 区分，`SimpleDNS` 的部分字段在加载空配置时无法命中内置默认值。
4. **T10 校验日志持久化不一致**：
   - 执行方声称 16/16 内核校验通过并指向 `target/t10/matrix/results.json`，但该目录被 `.gitignore` 排除，代码库未提交任何不可篡改的校验结果记录文件。
