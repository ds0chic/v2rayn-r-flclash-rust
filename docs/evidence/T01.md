## 4. 五个 spike 结论

| Spikes | 结论 | 证据 |
|---|---|---|
| S1 帧时间骨架 | **通过（仅骨架，不设最终门禁）** | `benchmarks/T01/frame_times.json`；`lib/perf/perf_harness.dart` |
| S2 EnableHWA / 软件渲染 | **有限支持** | `t01_software_rendering.png`；见下 |
| S3 证书来源映射 | **通过（仅 API 可用性）** | `crates/application/tests/cert_sources.rs`；见下 |
| S4 架构/插件矩阵 | **Windows x64：通过（实测）**；ARM64/macOS/Linux：**需真实环境验证** | 构建产物 + `bridge_api.dll` PE 头 |
| S5 单实例探针 | **通过** | `crates/application/tests/single_instance.rs`；见下 |

### S1 — 帧时间骨架（`benchmarks/T01/frame_times.json`）

- 方法：`SchedulerBinding.addTimingsCallback` + 脚本化滚动 600 步（每次 `jumpTo`，步间 8ms）。
- 构建模式：**release**；行数：**10,000**；样本数：**581**。
- 摘要（微秒）：`build_p50 = 12078`、`build_p95 = 19301`、`raster_p50 = 3692`、`raster_p95 = 4153`。
- 结论：链路可测量；本数据仅为骨架参考（脚本 `jumpTo` 会强制整表重建，不代表真实拖拽滚动）。**不作为最终性能门禁。**

### S2 — EnableHWA（FLD-CFG-062）

- 上游 WPF 通过 `RenderOptions.ProcessRenderMode = SoftwareOnly`（`MainWindow.xaml.cs:151-154`）在 `!EnableHWA` 时切软件渲染。
- Flutter Windows runner **没有等价的运行时 API**；但引擎支持启动期 switch 注入。实测：
  `FLUTTER_ENGINE_SWITCHES=1`、`FLUTTER_ENGINE_SWITCH_1=enable-software-rendering` 启动 release exe，窗口正常出现且界面正确渲染。
- 结论：**有限支持** —— 可用进程级引擎 switch（需以环境变量/启动参数在进程启动前设置，进程内无法运行时切换，需重启）；`EnableHWA` 若要迁移，应重新定义为“启动参数 + 引擎 switch”，而非运行时开关。

### S3 — 证书来源（rustls）

- `rustls-pemfile 2.2.0` 读取 T00 夹具：`mozilla_roots_pem` **121** 张、`chrome_roots_pem` **104** 张，全部解析成功。
- `rustls-native-certs 0.8.4` 读取系统信任库：**67** 张，`errors=0`。
- 结论：**通过（API 可用性）**。Rust TLS 后端（`rustls` + `rustls-native-certs`，浏览器根用 `rustls-pemfile` 加载）能同时覆盖系统与浏览器根证书；未做证书选择/优先级策略（属后续任务）。

### S4 — 架构/插件矩阵

- **Windows x64 release：通过**（本机真实构建 + 运行 + 截图）。
- Windows ARM64 / macOS / Linux：本任务**未构建、未运行**；只能给出“**需真实环境验证**”分类结论，不声称已支持。cargokit/podspec/gradle 骨架已随 `rust_builder/` 存在（FRB 生成），但不构成可运行证明。

### S5 — 单实例探针（F-DESKTOP-007）

- Rust `windows` crate `CreateMutexW` 命名锁：第一实例成功，第二实例 `GetLastError = 183`（`ERROR_ALREADY_EXISTS`）。
- 结论：**通过**。可在 runner 层实现单实例检测；本任务**不接管应用生命周期**（不注册/不拦截第二实例）。

## 6. 环境级问题（重要，登记为 T02 输入）

锁定的 Flutter 3.47.5 在本机 `flutter test`（软件渲染）下，`flutter_tester` 会随机/累积崩溃，退出码 `-1073741819`（`0xC0000005`），无 Dart 栈。实测：

- 单个 `MaterialApp(Text)` 连续建树约 25 次崩溃（内容无关）；
- 单个真实页面构建约 10–30% 崩溃；
- 与 `two_dimensional_scrollables` 无因果（改用自研行虚拟化同样崩溃）；
- 与 PATH/DLL 注入、视窗尺寸覆盖无关（清洁 PATH、去掉尺寸覆盖后仍复现）；
- `--enable-impeller` / `FLUTTER_TEST_IMPELLER=true` 未消除（4/10、1/10 波动）。

缓解：每个 widget 测试文件仅一次页面构建 + `dart_test.yaml: concurrency: 1` + `tools/flutter_test_retry.ps1` 重试。并已修复真实确定性缺陷：工具条/状态栏改为横向可滚动，消除 `RenderFlex overflow`（在 1024×700 下曾 20/20 失败，修复后 1/10）。

原始日志：`target/flutter_test_attempt_*.log`、`target/t01_*.log`（本地 scratch）。
