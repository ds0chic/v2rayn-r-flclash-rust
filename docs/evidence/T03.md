## 2. 本轮改动

### runtime
- `adapter.rs`：新增 `CoreLocator::with_roots`（可测），补齐 locator 单测
  （版本优先/固定版本/override/NOT_FOUND）。
- `job.rs`：新增 `KILL_ON_JOB_CLOSE` 真实子进程终止单测（`cmd /c ping`，
  5s 上限）。`io::Error::other` 化。
- `sha256.rs`：`chunks_exact` clippy 允许项。
- `lib.rs`：`#![allow(clippy::result_large_err)]`（与其他 crate 一致）。

### net_host
- `session.rs`：lease 判定抽为纯函数 `reclaim_due` 并加单测；**成功 Running
  时日志保持 `Applied`（不再写 `Finalized`）**，使 net-host 硬杀后能被恢复；
  spawn/job 失败时补写 `Finalized`，避免幽灵恢复；`heartbeat_miss` 字段移除。
- `server.rs`：watchdog 增加 server→client `heartbeat` 事件；连接存续即租约存续。
- `journal.rs`：恢复时若 terminate 与正在退出的进程竞态失败，则复核身份，
  进程已消失即视为已清理；新增 `[net_host] recovery ...` 日志。
- `dacl.rs`：新增当前用户 SDDL 构建单测。
- `bin/t03_client.rs`：新增 `apply-hold`；apply/apply-bad 遇到 `IpcResult::Error`
  时以退出码 3 失败（不再误报 `APPLY_OK`）。

### application
- 新增 `net_host_client.rs`：真实 `NetHostClient`。**Windows 同步管道句柄按
  FileObject 串行，`try_clone` 读写会在两个线程间死锁**，因此控制请求使用
  独立短连接（同线程写+读，调用方 `recv_timeout` 限时），事件使用独立长连接
  （同线程订阅后只读，保持租约）。自动拉起顺序：
  `V2RAYN_R_NET_HOST` → 当前 exe 同级 → 祖先目录 `target/debug|release`。
- `runtime_client.rs`：`RuntimeSnapshot` 扩展 PID/创建时间/端口/session/hash/
  operation/error；trait 增 `subscribe_events`（默认 no-op）。
- `engine.rs`：新增 `production()`、`stop_runtime()`、`subscribe_runtime_events()`；
  `cancel_job` 先询问 runtime 再落到 JobManager。
- `snapshot.rs`：快照携带运行时事实。
- 新增 `examples/t03_probe.rs`：脱离 FRB 验证客户端。

### bridge_api
- `engine()`：`cfg!(test)` 用内存引擎，生产用 `NetHostClient`。
- `apply_runtime`：改用 `config_codegen::generate_xray` 生成冒烟计划
  （mixed/socks 入站 `127.0.0.1:11808` + `freedom` 出站；**严禁 10808**）。
- 新增 `stop_runtime`；`get_snapshot`/`apply_runtime`/`stop_runtime` 改为
  FRB 异步函数，避免阻塞 UI 线程。
- `subscribe_events`：一次注册 net-host 事件转发到 FRB 流。
- `SnapshotDto` 扩展 `host_alive/runtime_pid/...`；新增 `StopRuntimeResult`。
- 新增 `#[frb(ignore)] xray_smoke_config_json()` 与
  `examples/t03_smoke_config.rs`，供用真实 Xray 校验生成配置。
- `flutter_rust_bridge_codegen generate` 后二次运行无 diff（已验证）。

### Flutter（apps/desktop）
- `lib/features/runtime/runtime_bridge.dart`：`RuntimeBridge` 抽象 + FRB 实现 +
  测试用 `SyntheticRuntimeBridge`。
- `lib/features/runtime/runtime_controller.dart`：状态仅来自 snapshot/events；
  apply/stop 失败保留结构化错误，不被后续 snapshot 覆盖（**禁止假 Running**）。
- `main_shell.dart`：工具条「启动测试会话 / 停止」+ 状态 chip。
- `status_bar_view.dart`：真实 `state / host / PID / 端口` 与结构化错误。
- `app.dart`：生产启动时订阅 + 首次快照；`V2RAYN_R_AUTOSTART=1` 证据钩子
  （真机启动即 apply，非伪造状态）。

## 7. 未决项

1. **apply 仍为一次性完成语义**：net-host 在 readiness 完成后才回包，UI 在
   启动期间看到 `Checking`（由事件推送）；后续 T03+ 可改为“接受即返回 + 事件
   驱动完成”以支持取消。
2. **cancel_job**：net-host IPC 合同无取消操作，`NetHostClient::cancel` 返回
   `NotCancellable`；应用层取消仍由 JobManager 负责。
3. **事件流无断线重放**：长连接断开后按 `EVENT_RECONNECT` 重连并重新
   `SubscribeEvents`，但未按 epoch/seq 回放缺口（当前 T03 仅需状态同步）。
4. **Windows 同步管道**：客户端未使用 overlapped I/O；超时的控制请求线程会
   残留至对端关闭。生产为进程级单例，影响可忽略；后续可改 overlapped。
5. **Flutter 运行控制仅为最小接线**：未接入真实节点/订阅/路由配置，冒烟计划
   固定端口 11808。
6. 真实代理流量仍不过 Flutter/FRB；系统代理与 TUN 未接入（T13/T14）。
