## 修复合同与实现

1. **net-host 真正执行 process_graph**：`session::precheck_plan_with_exe` 新增 `prepare_sidecars`：按 `process_graph.start_order()` 解析 target 之外每个节点（跳过 `TUN_PROCESS_ID`）的 adapter/locator/hash/`test_args`（在停旧会话**前**，与 RR-10 一致）。`start_prepared` 在主核前按序 stage/spawn 每个 sidecar（各自 Job Object + 日志），若侧车端口非 0 则 `wait_socks_port`（SOCKS5 greeting `05 01 00`→`05`，mirror `WaitForProxyPort`）；任何失败按**逆序** `stop_sidecars` 回滚，主核未起即中止。`Session.sidecars` 持有侧车，`terminate_and_wait` 逆序停（侧车先于主核）。
2. **预 SOCKS 真配置**：`codegen::generate_pre_socks_config(core, listen, port)` 用既有冻结生成器（Xray/sing-box）生成真实 SOCKS listener 配置；`engine::build_runtime_plan` 的 sidecar 节点 `ConfigSource::Inline.body` 改为该真配置序列化（替换原 `v2rayn.presocks.plan.v1` 描述）。
3. **Custom 预 SOCKS 默认核**：`engine::pre_socks_of` 的 Custom 分支 `sidecar_core` 从 `node.core_type` 改为 `Self::custom_default_core(settings)`（`CoreTypeItem` 的 `Custom` 绑定，缺省 Xray），对齐 `GetCoreType(null, EConfigType.Custom)`。legacy+TUN 仍强制 sing-box。
4. **全核 adapter 候选**：`runtime::adapter` 新增 V2fly/V2flyV5/Mihomo/Hysteria/NaiveProxy/Tuic/Juicity/Hysteria2/Brook/OverTls/ShadowQuic/Mieru adapter（+ 原 Xray/SingBox），`CoreType::PROXY_CORES`（14）全部 `Some`，仅 `App`（v2rayN 自身更新身份）`None`。`CoreAdapter` 新增 `exe_names()`（默认 `[exe_name]`），候选名镜像冻结 `CoreInfoManager`（如 mihomo `GetMihomoCoreExes` 全表 + `clash`/`mihomo`；naive `naive`/`naiveproxy`；hysteria2 平台后缀；sing-box `sing-box-client`/`sing-box`）。`CoreLocator::resolve` 新增 `find_candidate_exe` 候选回退（pinned 版本目录或 core 目录下各子目录逐一候选）。
5. 不删任何 `CoreType` 枚举、不降分母；FIX-13 图结构与 FIX-07 语义不变。

输入/输出/错误/取消/权限/持久化及生效语义：
- 输入：`RuntimePlan.process_graph`（sidecar 节点 + 依赖边）、`AppSettings`（TUN/LegacyProtect/core_type_item）、`Profile.pre_socks_port`。
- 输出：多进程真实启动（侧车先、主核后、等待端口）；侧车真核心配置；adapter 候选定位。
- 错误：sidecar 无 adapter/chip 缺 exe/`test_args` 失败 → 停旧会话前结构化失败；侧车 ready 超时 → `error.readiness_timeout` 且回滚，主核未起。
- 取消：主核阶段失败逆序停侧车；旧会话 RR-10 `try_restore` 保留。
- 权限：全部普通权限子进程，各自 Job Object；不写系统代理/TUN。
- 持久化：无。
- 生效：下一次 `apply_plan` 即执行完整图。
