# T18 决策 — 性能预算、阈值与测量口径

本文件记录 T18 采用的预算、阈值与“通过/不通过”解释，避免事后为通过而改门禁（方案 §16）。

## 1. 预算来源

- 直接引用 `outputs/V2RAYN_FLUTTER_RUST_PLAN.md` §16 的设计目标，不新增更严的硬门禁。
  关键目标：40Hz/60Hz 表格滚动 UI/raster 分别 p95 ≤ 16.7ms、超预算帧占比 ≤ 1%；
  冷启动可交互 p95 ≤ 2s；内存首要门禁是“无持续增长”。
- T18 只做**短时采样**，不宣称 24h soak。稳定性以“重复操作无残留/无漂移/无单调增长”为判据，
  样本量与限制写进 `docs/evidence/T18.md`。

## 2. 本回合采用的可执行阈值

| 项 | 阈值 | 解释 |
|---|---|---|
| 冷启动到首帧（release） | 记录 p50/p95，不设硬失败；对照 §16 的 ≤2s 目标做说明 | 本机发布流程包含 DLL/引擎初始化 |
| 60Hz 帧预算 | `16.7ms`（build+raster 合计） | 用于 `dropped_rate` 统计，逐帧与预算比较 |
| 日志环形缓冲 | 10000 行 / 10MiB（上游与代码既有 `DEFAULT_MAX_LOG_*`） | 注入 10 万行后 `retained + dropped == injected` |
| 会话循环 | 20 次 apply/stop 全成功、端口释放、无自有残留进程 | 任一失败即定位；不按进程名统计泄漏 |
| 应用重开 | 同一数据目录 10 次，配置 SHA-256 与 revision 不漂移 | 由 Rust 引擎级测量 |
| 运行会话 CPU | 仅报实测消耗秒数；空闲冒烟会话预期接近 0 | 不做整机百分比换算（无多核基线） |
| 内存 | 报 WorkingSet p50/max；空闲 vs 10k 行对比 | 无持续增长趋势判据 |

## 3. 方法学决策

- **冷启动**：以“父进程 `Start-Process` 前时间戳 → 子进程写出 `first_frame` 标记文件”为主口径，
  另记录进程内 `main() → 首帧` 时间。两者都落盘，避免把进程重开冒充真正冷缓存。
- **滚动**：沿用 T01 S1 的脚本化 `jumpTo` 骨架（每步 8ms，600 步）。它强制整表重建，
  是**上界探针**而非真实拖拽手势；结论必须与 raster 分开看，不能只报总分。
- **数据来源**：release 模式下用 `T18BridgePort` 直接把合成行投到真实虚拟表格，
  不读用户数据库、不启内核、不碰 10808。
- **稳定性**：异常路径复用既有 `services/net_host/tests/t03_faults.ps1`；
  只统计本次脚本启动的 PID，宿主自有的 `xray.exe` 不计入泄漏也不被终止。
- **只读盘**：以“把 `guiNConfig.json` 替换为目录后再保存”制造真实写失败，验证错误呈现与旧值保留；
  这不是真正只读卷，限制已明示。

## 4. 未采纳的更强口径（明示为未覆盖）

- 120Hz/8.3ms 独立硬件档位、真实拖拽手势、24h soak、多核归一 CPU%、真只读卷。
- 端到端“设置→真实运行内核”链：见 `T18-findings.md` 的 apply_runtime 未接线缺陷。
