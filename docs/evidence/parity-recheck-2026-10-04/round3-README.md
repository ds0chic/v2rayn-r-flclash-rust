## 当前发布物口径变更

审查开始时的 ZIP SHA-256 `6e9e2855…` 与旧报告对应；随后并行刷新。总览写入时 `dist/v2rayN-R-1.0.0+1-windows-x64.zip` 的完整 SHA-256 为 `ffe8e0a46d1e96aac437c5074961710537c1c597f0b6d33de1500dface4dadd9`，与 `dist/SHA256SUMS` 一致；ZIP CRC 校验通过，包内 `build-info.json` 标 `git_commit=f328d0f91fe95ce5ff64d1b56d382c9e25c1c68d`、`git_dirty=true`、`smoke_armed=false`。因此**最新包的哈希正确，但构建时工作树非干净状态**；此标志本身不说明未提交的文件是否进入二进制。应先稳定工作区、重新从干净 HEAD 构建并复算哈希；即使如此，前述业务 P1 和平台阻断仍在，不能仅以重打包宣称正式版。

实施上先为 PAC、预 SOCKS、备份 A→B→A/替换语义、右键目标、UDP 路径补能在生产入口失败的合成测试，再修代码并跑同入口 Windows 操作。TUN、系统代理、自更新和真实多核需在隔离环境按项目约束验收；每项需走 UI→Rust→持久化/重开→实际配置/进程/平台效果，未验证维持 `implemented/identified/blocked`，不下调台账分母。
