## 3. 先冻结真实用户操作合同

**节点身份必须分开：** selectedIds（批量选择）、primaryId（当前键盘/单行目标）、activeProfileId（持久化默认）、appliedProfileId/sessionId/revision（实际运行）。勾选、高亮、默认标识、正在运行标识各自有意义；禁止用一个 active 布尔代替四者。

1. 普通单击只按原版选择；Ctrl/Shift 多选不启动。双击根据 `DoubleClick2Activate` 执行编辑或设置默认；Enter 按原版命令。相同默认节点的 no-op 不得伪造一次成功运行。
2. 新增显式启动/应用按钮须名字与目标一致。若称“启动选中节点”，点击时冻结有效 primaryId；先验证身份并保存默认，取得新 desired revision，再提交该 ID 的不可变计划。没有选中时按原版有效默认/默认恢复合同处理，无法恢复就明确提示选择。不得静默使用另一个旧活动节点。
3. F5/“重启服务”保持原版重载默认配置语义，不擅自根据鼠标高亮切换节点。显式“重试”重新提交计划，历史失败是诊断，不是拒绝新命令的条件。
4. 保存失败不改变持久状态；保存成功应用失败必须显示这两个结果，同时显示仍运行的旧会话或停止事实。回滚成功不等于新配置成功应用。
5. 启动就绪至少核对受管进程存活、真实监听、发布的实际端点与计划；协议握手/真实请求是另一层验收。只有存活 PID、配置校验通过、端口打开都不足以宣称代理流量可用。
6. UI 命令状态和 host 运行状态分离。点击立即显示“正在请求/校验/启动”；这个本地 pending 不可冒充 net-host 的 Running 或 Starting 事实。等待期间仍可选择、滚动、打开错误详情；冲突命令串行或合并，取消有明确边界。
7. 未下载内核是正常首用分支：解释缺少哪个内核，提供原版可达的安装/更新入口；完成后可以重试，不重装应用、不靠环境变量、不永久陷入旧错误。
8. 当前订阅来自用户所在的节点分组；订阅设置对话框自己的选中行不能抢占它。冻结原版All组的“更新当前”更新全部合法非空HTTP(S)订阅，普通空URL组跳过，指定组只更新该组。更新替换范围保持IsSub合同，保留原版要求保留的节点、稳定身份、默认引用和统计。
9. 参数/路由/DNS 窗口遵守各自原版的“应用/确定/取消/关闭”时机。不得用统一的“点任何保存都重启”替代；先逐项读冻结源码，再建立持久化与生效合同。
10. 拖列宽、分隔条、滚动和菜单开闭属于 UI 操作，不应触发运行快照、全库刷新或同步磁盘写。

## 5. 关键技术修复设计

### 5.1 启动、重试、错误恢复

- 用共享用例处理各入口，参数带明确 `targetId`、操作原因、expected revision、operation id；普通“设为默认”的幂等合同与显式“启动/重试”的合同分开。
- revision 从 AppEngine 本地持久状态读取，不为读版本先做一次可能等5秒的 net-host snapshot。不同默认节点变更须推进desired revision，相同默认保留原版幂等；持久化失败不留下内存active先变的伪状态。后端原子核对身份/版本并构建不可变计划；不能靠 UI 两次读拼出一致性。
- 快照返回“连接失败/过期事实/历史运行错误/当前操作错误”等独立信息，保留最后可信事实并标 stale。不要将失败转空快照，不要将历史错误当新命令的前置条件。
- 合并重复 refresh，避免 `reload→refresh→apply→refresh` 与事件刷新积压；记录 session/epoch/operation 以淘汰晚到的旧响应。事件序号缺口触发一次权威 reconcile，不能只打印日志。
- 原因修好后不必重启 GUI 即可重试；失败不丢默认配置；如果恢复旧会话，应显示“新配置失败，仍运行旧配置”。
- 快速重开复用host时，从host恢复实际目标ID/内核/端点/版本/配置hash，禁止用新的desired active或默认Xray猜旧会话的归属。所有退出和自更新交接统一等待受管停止、平台恢复、任务/统计flush，在有界deadline后报告未完成状态。
- 应用成功后的平台协调统一从 applied session 实际端口更新代理/PAC/监控/托盘；仅修改DB或高亮不触发系统写入。

### 5.2 延迟与并发

- 把可能 I/O、DB批处理、文件解析、压缩/哈希、IPC、网络的 FRB 方法改为异步；仅经测量证明极短的纯内存读取保留 sync。不能看到 Future 就宣称内部没有阻塞；Rust受限工作池执行阻塞任务，Tokio任务不被长时间占用。
- `req_mutex` 改为有界命令调度/总deadline，包含排队、连接、写、读、校验和启动。控制操作串行，快照优先读 host 的权威快照缓存或合并读；不得用无限新线程假装取消了超时任务。
- 取消/超时必须区分“尚未提交”和“已经提交但结果未知”；后者 reconcile，不自动重复执行或声称已回滚。停止正在验证/启动中的会话由 net-host 状态机处理，而不是前端乱序发送 Stop。
- 表格用 Rust 摘要查询/分页/稳定排序，草稿详情按ID读取；测速/流量只推送增量结果，不每150ms全库拉取两次。批量写事务后只刷新一次。
- UI状态保存按drag结束或短debounce合并，异步原子写；磁盘flush从 monitor共享锁中移开，先复制待写快照再在后台落盘，失败明确登记。
- 单击选择从双击识别等待中移开；按原版在正确pointer阶段及时反馈，捕获点击时Ctrl/Shift/targetId，不在300ms后的回调读实时键盘状态。双击业务独立识别，避免pointer选择与onTap重复toggle；右键、拖选与取消手势保持同一对象合同。
- Riverpod watch 使用所需切片，日志/流量不导致整窗主题与表格重建；连接/策略组刷新采用单在途、最新会话/最新generation胜出，隐藏页取消页面刷新但保留后台采集。

### 5.3 底部、表格、菜单和窗口

- 按原版恢复底栏分区和先后：本地/局域网两行 → TUN → 系统代理下拉 → 路由下拉 → 运行节点/用户运行信息 → 代理/直连速度两行。以原版XAML实测尺寸为基准。
- 可操作区域有明确下拉箭头、标签、边框/hover/focus；只读信息统一文本样式。host、PID、epoch、seq、revision、技术code放诊断详情，不铺满常规底栏。
- 错误呈现为可读原因与行动：“缺少Xray → 安装内核”“端口被占用 → 修改端口”“配置无效 → 回到对应字段”“后台失联 → 重试连接”。技术细节可展开、复制脱敏内容；失败信息不能被下一条测速或订阅通知立即盖掉。
- 800px最小窗口和1200×800基准必须所有核心操作可达；长节点名省略/tooltip，只读附加信息可折叠，不以缩小字体或整栏横滚掩盖问题。100–200% DPI与文字缩放实测，不只模拟屏幕尺寸。
- 右键菜单单一 session 管理：新右键替换旧菜单；点击外部/Esc/失焦关闭；执行后恢复表格焦点；子菜单切换不闪退；菜单是否保留多选严格按原版；坐标/目标在打开时冻结，删除/筛选后禁止对过期ID执行。
- 参数与路由已经有独立原生窗口实现，应修其Owner、modal、snapshot/version、保存结果回传、失败留窗和焦点，不能再次把“创建第二窗口”当成需求完成。其他窗口逐项与WPF inventory对照。

### 5.4 数据与订阅

- 生产存储打开失败应进入可见的恢复/只读状态，禁止退到内存后仍显示保存成功。启动恢复先验证数据目录、DB/配置版本、可写性和迁移结果。
- IsSub是需逐入口核对的来源语义；冻结ProfileItem默认true，普通新建/clone并未统一改false；手工AddBatch(...false)明确写false。先按原版保留这些差异，不能擅自统一所有手工来源。成功更新仅替换该组IsSub=1集合，在同一提交用例内重用/重映射稳定ID、活动节点和统计；不按Subid清空整个组。若要把所有手工入口统一false，应独立登记改善决策与数据升级，不能冒充原版行为。
- 订阅候选抓取/转换/解析/校验成功后才激活；取消和单个失败不损坏原有集合。对于原版确实允许的部分成功，按原版明示结果，不能暗中全空替换。
- 节点页当前分组接到持久 `SubIndexId`，保存/更新/编辑/新增各入口都从同一当前组读取，重开与原版一致；对话框选中态是局部状态。
- 全组手工导入只持久化一次，消除Rust批写后Dart再次N次save。数据库写、JSON配置交换、UI重载、运行应用的结果分别可观察。
- ui_state迁至明确可写的数据目录，并兼容读旧exe旁状态；写入失败有可见诊断，禁止在Program Files静默丢失布局。

### 5.5 设置、路由、DNS和资源

- 每个字段必须有默认/缺省/null/空串、取值范围、联动、持久键、消费点、原版生效时机及不同内核支持范围。保存和重开不是字段闭环，必须验证生成配置或平台实际效果。
- 原生窗口每次提交携带对应打开/读取时revision，过期草稿不能覆盖另一窗口/热键/后台修改。参数窗口取消不写；**路由窗口必须单独遵守原版**：策略修改即时保存，子编辑确定后提交，主路由窗关闭时根据IsModified通知Reload。当前全窗草稿+确定/取消是语义回退，不得继续按新逻辑写测试“证明一致”。每次原版提交用例内部使用事务，失败回滚该次提交；不把所有提交推迟到全窗确定，也不在关闭时撤销此前已确认的子编辑。
- 原生snapshot envelope必须带成功标记、内容、revision和错误；未ready/解码或规则读取失败禁提交、提供重试。合法空库与读失败严格区分，不能把通道错误当用户删除全部的请求。
- 运行应用在DB提交后单独处理，等待结果并反馈；自启写失败不能悄悄忽略。决定是否保留已保存配置按原版与明确合同，不用假的跨OS原子事务。
- 参数窗口原版也可先关闭再由主窗Reload；修复不是强制改成应用成功才关窗，而是确保本次保存/平台/运行结果在正确位置可见。跨engine请求带request ID和deadline，缺channel/丢回包要明确失败或查询提交结果，不永远pending、不重复提交。
- DNS草稿基线按稳定fieldId/controller身份保存；原值相同不会合并字段，预设与外部刷新不能覆盖用户已改字段。确定保存后接回原版Reload时机。
- 内置规则导入、Geo/SRS下载、路由/DNS模板、订阅转换、区域预设、证书信任源必须核对真实消费者。仅提供解析器、URL保存、提示“已刷新”不算移植完成。

## 7. 验证方式：回到未武装正式入口

**第一道：无原生库的故障注入。** 重试、在途合并、超时/取消、乱序、DB/窗口版本冲突、平台拒绝、部分保存失败。mock只证明分支合同，不证明外部内核和系统状态。

**第二道：真实FRB + SQLite重开。** 临时数据目录、真实DLL、独立命名管道、受管run目录、合成节点/订阅/原版配置夹具。命令从UI可见入口发起，检测DB/JSON，关进程重开核对，不通过override把生产仓储替成Synthetic。

**第三道：未武装发布包 + 真实内核 + 本地服务器。** 从发布zip独立解压，移除开发核路径环境变量，按普通用户方式安装/定位锁定核；选择节点、点击启动、等就绪，通过SOCKS/HTTP请求本地合成服务，核对内容及停止后的端口/进程。然后缺核/缺文件/坏配置/端口占用/异常退出并重试。测试无须用户节点或远端账户。

**第四道：冻结原版对照。** 同一合成数据/相同尺寸DPI/相同输入序列运行WPF与重构版；对比选择、右键生命周期、分组、字段、保存生效、取消和错误反馈。截图比较检查结构与可读性，动作日志验证行为，不能只有空窗口美观截图。

**第五道：隔离OS测试。** 当前宿主不改代理/默认路由。TUN、系统代理即时生效、权限/Run-key/退出恢复在具备明确授权的隔离VM或独立测试机执行。空闲11808只解决监听冲突，解决不了auto route改默认路由、DNS及网卡的问题。无隔离条件写未验证和阻塞条件，继续做不依赖它的修复。

证据最低格式：固定Git commit、发布包SHA256/armed=false、工具/系统/DPI/内核版本、合成fixture ID、操作时间线、预期/实际、持久化检查、applied会话核对、脱敏错误、截图、退出清理结果。故障注入结果标明fake，历史证据标明旧commit。

必须禁止：用AUTO_SMOKE绕过被测按钮；只直接调用Rust函数替代UI；预先setActive掩盖第一次选择失败；指定开发Xray路径掩盖安装/locator；仅检查pid/port而不发请求；以另一平台cargo check当GUI运行；把失败用例改成“预期失败因此项目通过”。
