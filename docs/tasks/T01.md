# T01 任务卡 — 技术可行性验证与依赖冻结

> 依据：`V2RAYN_FLUTTER_RUST_PLAN.md` §18（T01 行）与 §19 固定格式；前置为 T00 台账。

任务 ID：T01
本次唯一用户流程：构建一个最小 Flutter Desktop + Rust（FRB v2）release 应用，在真实虚拟化节点表格（10,000 行合成数据，非 mock 表格组件）中完成一条键鼠操作流，并验证 UI→FRB→Rust→事件回传的完整链路可测量、可打包运行。

前置任务及已验证证据：
- T00 完成：`compat/upstream-lock.json`、`compat/features.yaml`、`compat/fields.yaml`、`compat/actions.yaml`、`compat/layouts.yaml`、`compat/platform-matrix.md`、`fixtures/source/`、`docs/evidence/T00.md`。
- 未决项约束：`docs/evidence/T00.md` 的 unresolved 清单不得被本任务的任何结论“顺手关闭”；只能新增 T01 证据。

对应 feature / field / action / layout ID（本任务只验证承载能力，不改行为合同）：
- LAY-MAIN-001 / LAY-MAIN-002 / LAY-MAIN-003（三布局壳体可行性，仅验证窗口与分区能搭起，不验收几何精度）
- LAY-PROFILES-001 / LAY-PROFILES-002（节点表虚拟化与列模型可行性；14 列默认顺序见台账）
- ACT-PROF-001..043 中涉及键盘/多选/排序/滚动的条目（只验证输入事件在虚拟表格上可区分：Ctrl 修饰、Enter、Delete/Back、Esc、T/B/U/D、双击、拖放、右键）
- FLD-CFG-062（EnableHWA）、FLD-CFG-081（HideColumnIpInfo，仅作为渲染/列状态样例）、FLD-CFG-156..158（WindowSizeItem，窗口尺寸持久化样例）
- F-DESKTOP-007（单实例可行性探针，按台账 unresolved 状态仅验证 Flutter/runner 是否具备等效能力）

输入、输出、错误、取消、权限、持久化及生效语义：
- 输入：合成 10,000 行节点数据（不真实姓名/地址，使用 RFC 文档地址段与示例域名），由 Rust 侧生成并通过 FRB 流式分页获取；不得使用示例节点冒充真实数据源。
- 输出：release 构建产物可运行；表格操作以事件计数与帧时间线为证据；依赖锁文件提交（`pubspec.lock`、`Cargo.lock`、FRB 三处同版本）。
- 错误：FRB 初始化失败、DLL 架构不匹配必须显式报错；构建脚本失败即任务失败。
- 取消：本任务不实现业务取消；只验证短任务的 FRB 异步调用不会阻塞 UI 线程（用合成长循环在 Rust 侧占用 blocking pool 验证）。
- 权限：不申请任何系统权限，不修改系统代理与网络设置。
- 持久化：仅窗口尺寸/列状态草拟到本地文件（可临时格式），验证“保存-重开-恢复”闭环存在；不得把它当作最终 AppSettings 合同。
- 生效语义：本任务不生成任何真实内核配置，不启动内核。

允许修改的模块：
- 仅新建：`apps/desktop/`（Flutter 壳）、`crates/bridge_api/`、`crates/application/`（最小）、`crates/domain/`（仅验证需要的类型）、`tools/`（构建脚本）。
- 依赖决策记录：`docs/decisions/T01-*.md`。

禁止改变的已有行为：

- 不实现任何 T02 之后的业务语义（无数据库、无订阅、无内核进程管理、无系统代理）。
- 不得用占位页面/全 mock 后端声称“可行性通过”；表格虚拟化必须是真实组件渲染 10,000 行。
- 不得引入 Electron/Tauri/WebView、第二套状态管理或第二个 IPC 通道。

测试夹具和原版预期：
