## Actual gap (confirmed empirically, serde_yaml 0.9.34)

`crates/application/src/mixin.rs::parse_mapping` fed
`serde_yaml::from_str::<Value>` output straight into `generate_mihomo`.
A scratch probe (temporary integration test, since deleted) showed:

- `<<: *anchor` / `<<: [*a, *b]` are NOT flattened: they survive as a
  literal `"<<"` key whose value is the aliased map/sequence, and the
  `<<` entry is re-emitted by `serde_yaml::to_string` into the generated
  mihomo file. The merge the author expressed silently never applied.
- Plain aliases (`copy: *b`, no merge key) already expand by cloning.
- Dangling aliases (`<<: *missing`) already fail at parse time.
- `<<: 42` (scalar merge value) parsed as a literal key (no error).
- Duplicate mapping keys fail at parse time
  (`duplicate entry with key "mode"`).

So the missing piece was exactly the upstream `PreprocessYaml` step.

## Fix location (deviation from task suggestion, registered)

The task suggested `crates/config_codegen/**`. Grep proves that is not
where the generator lives: `config_codegen` contains no mihomo/YAML code
at all (only Xray/sing-box structured generators; its `Cargo.toml` has no
YAML dependency). The mihomo custom-YAML generator is
`crates/application/src/mixin.rs::generate_mihomo`, reached via
`crate::codegen::mihomo_body_for_plan` from the `engine.rs` native_custom
branch (SP-24 G-06). The pre-pass is implemented there, where all three
YAML inputs (base/mixin/tun) are parsed — no new dependency, no
`Cargo.toml`/`Cargo.lock` churn. Files changed:

- `crates/application/src/mixin.rs` (only source file touched):
  - `resolve_merge_keys` + `merge_source`: recursive `<<` flattening at
    every mapping level. Explicit keys win over merged keys;
    `<<: [*a, *b]` earlier sources win over later ones; the `<<` entry
    is removed. A `<<` value that is not a mapping/sequence-of-mappings
    is `FIELD_FORMAT` (fail closed, same message id
    `error.mixin_yaml_invalid`, field `base`/`mixin`/`tun` preserved).
  - `parse_mapping` runs the pre-pass after `serde_yaml` parse (which
    keeps resolving aliases and rejecting dangling anchors/duplicates).
  - Deliberate superset of upstream: the pass applies uniformly to base,
    mixin and tun texts (upstream only pre-scans the base file behind a
    `Contains("<<:") && Contains('*') && Contains('&')` heuristic).
    Plain-YAML documents pass through unchanged.
- This evidence file (no ledger CSV / FLD / manifest edits; no commit).

Not touched (per hard constraints): `bridge_api`, `ipc_contract`,
`services/`, workspace `Cargo.toml`/`Cargo.lock`, FRB files.
Untracked/parallel-batch files in the tree (`tun_plan.rs`,
`config_codegen/...`, other `waveB-*` evidence) are other workstreams';
`git diff -w` equals `git diff` (no whitespace-only edits by this card).
