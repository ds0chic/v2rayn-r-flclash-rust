# 节点右键菜单与界面间距专项审查

日期：2026-10-03。应用源码基线：`d7fbe80`。冻结上游：v2rayN 7.25.4，commit `7d6a967c18c697f28dc6917122ed3a4993fcf336`。本轮只新增集成测试和审查证据，没有修改应用实现。

## 结论

用户反馈可以在真实 Windows Flutter 窗口中复现。菜单定位、表格内点击关闭、Esc 焦点优先级均有明确错误；右键触发区域也与上游 DataGrid 的声明范围不同。拥挤来自原版入口布局被改动、控件尺寸没有统一、文字/快捷键/表单之间的间距不足，不能只把全局 padding 调大。

本审查接续 `docs/evidence/frontend-journey-2026-10-02/README.md` 的正常使用流程审查。下述修复顺序以完成用户流程为单位，不允许把“菜单项存在”当作交互已经迁移完成。

## 代码原因与处理边界

1. **坐标空间混用。** `profiles_table.dart:357` 将 `details.globalPosition` 交给 `_showContextMenu`；`:431` 又直接传给 `MenuController.open(position: ...)`。锁定 Flutter SDK 的 `raw_menu_anchor.dart` 明确要求 anchor 本地坐标；`material/menu_anchor.dart` 的定位逻辑再加 `anchorRect.topLeft`。实际 171 的偏移与这一调用链吻合。
2. **菜单内部命中区域覆盖整张表格。** `MenuAnchor.child` 是 Focus → Listener → 整个 TableView。点表格另一行在 anchor 的内部命中范围中，不能依赖默认 outside-tap 自动关闭。仅设置 `consumeOutsideTap` 不能解决这个范围错误。
3. **焦点被表格抢回，Esc 没有菜单优先级。** `onPointerDown` 无条件请求表格焦点；`_onKey` 没有先判断菜单是否打开，继续把 Esc 交给表格控制器。控制器清空选择，菜单本身却没有关闭。菜单关闭时原版表格 Esc 的停止测试等语义仍需保留，不能全局吞掉 Esc。
4. **触发覆盖不完整。** 只有数据单元格声明右键事件；行号、表头和空区域没有同一入口。冻结源码的菜单是 `DataGrid.ContextMenu`，当前实现不能用“每个数据单元格能弹出”代表整表行为已迁移。
5. **命令执行读取变化中的全局选择。** `_onContextAction` 当场读取 provider，而菜单没有定义打开时的目标和有效期。菜单不关闭、刷新保留隐藏选择等问题会叠加。需要固定打开时的操作目标或在目标上下文变化时关闭，不能把对象变化留给用户猜。
6. **组件默认尺寸与设计 token 不一致。** 主题设置了 compact，但本次菜单项实际高 40。锁定 SDK 的 MenuStyle 文档注明 visualDensity 不改变菜单项垂直尺寸，不能凭 compact 标记断言 32 的密度已经实现。
7. **菜单的层级和分组被改动。** 冻结 WPF 源定义17个根条目、4处分隔线；当前配置有19个根条目、1处分隔线，多了快速真延迟和混合测试两个根条目，UDP/测速相对顺序也改变。原版快测/混合有工具栏入口，不能随意复制到右键并宣称布局一致。原版“移至订阅分组”包含选择分组的子菜单和200宽 ComboBox，当前变成普通 MenuItemButton，默认 kind=notImplemented，实际接到 `shell.notImplemented`。这是源代码确认的结构/功能缺口，尚未做该移动操作的真实持久化测试。结构与中文资源抽取见 `upstream-menu-structure.json`。

相关台账：`LAY-PROFILES-001/002/004`，`ACT-PROF-001..013`、`ACT-PROF-014..026`、`ACT-PROF-032`、`ACT-PROF-038`。不要为了通过测试删除菜单条目、变更语义或降低台账分母。

## 右键菜单修复契约

以下是交给执行模型的具体约束。已经由源代码确定的结构必须恢复；原版默认弹窗事件细节先补实机证据，再冻结目标。每个动作一次执行，不能靠延迟关闭、反复 open/close 或丢焦点来碰巧过测试。

| 用户操作 | 必须形成的流程 | 原版依据/待补证据 |
|---|---|---|
| 右键未选中节点 A | 根据原版选择规则确定 A；在正确坐标打开唯一根菜单，菜单动作对应 A | 选择处理结合冻结 ProfilesView/VM；原生右键落选顺序待实机确认 |
| 右键当前多选中的 A | 保留原版允许的多选集合；批量动作对应这些 ID | 当前多选保留实测正常，必须回归 |
| 左键点菜单之外的另一行 B | 退出原菜单；依据原版是否透传该次点击来决定 B 的选择，禁止留下旧菜单操作新目标 | 当前“选择已变但菜单仍开”必须消除；一次还是两次点击选 B 待原版实机固定 |
| 左键点分组/工具栏/空白 | 关闭整条菜单链；按所点入口的正常流程继续，不执行旧菜单动作 | 事件范围必须区分菜单、子菜单和表格/其他控件 |
| Esc，根菜单打开 | 优先关闭菜单并正确恢复焦点；此次 Esc 不触发表格停止/清空选择 | 当前漏关与清空选择实测；原版焦点恢复对象需补对照 |
| Esc，子菜单打开 | 按冻结版行为退回正确菜单层级；不得泄漏到表格 | 未验证，须实机确定退一层或整链，不能凭模型记忆 |
| Esc，没有菜单/弹窗 | 保留原版节点表停止测试等快捷键逻辑 | ACT-PROF-038 与冻结 LstProfiles_PreviewKeyDown |
| 在另一个节点重复右键 | 对新目标重新建立上下文，旧菜单消失，最终只有一个菜单；不执行命令 | 开关时机、是否需要松开和原生焦点行为待补实机 |
| 鼠标由根菜单进入子菜单 | 子菜单可以稳定操作；不能因短暂离开根菜单而把全部菜单关闭 | 指针跨间隙、边缘反向展开、慢速/快速移动均需测 |
| 点“编辑”等命令 | 快照/确认有效目标 → 关闭菜单链 → 打开正确弹窗；取消后回到原来行、分组与滚动位置 | ACT-PROF-001；必须核对实际编辑的 node ID |
| 表格滚动/分组变化/过滤变化/删除刷新 | 用原版确定的退出或跟随规则处理；操作对象不得转移到别的行/隐藏选择 | 分组/过滤等显式上下文变化时建议关闭；滚轮行为待实机固定 |
| 窗口失活、最小化、关闭、布局切换 | 菜单不悬挂在旧窗口状态；恢复时不能自动出现旧菜单 | 原生 Windows 场景尚未验证 |
| 行号/表头/空白右键 | 菜单触发范围对齐 DataGrid；按原版选择状态启用对应命令，不得拿不存在行冒充对象 | 结构范围有源码证据，逐区域行为仍需补测 |
| 键盘菜单键或 Shift+F10 | 若原版支持，打开当前行菜单；菜单期间 ↑↓/Enter 的焦点归菜单，不能激活表格节点 | 原生默认能力待实测登记，不可当作当前已支持 |

实现建议：

- 坐标转换必须使用实际 anchor 的 RenderBox，明确调用方传入的是 global 还是 local；不要手工减固定侧栏宽度。加入移动、缩放、分隔条拖动和不同窗口大小的回归。
- 可继续使用 Flutter MenuAnchor，但把命中范围、焦点与上下文显式管理起来；也可用专门的菜单 overlay。禁止叠加两套菜单或在每格建立独立生命周期。
- 定义最小菜单会话数据：目标 IDs、当前行、所属分组/视图上下文、打开位置与焦点恢复对象。它只用于 UI 命令目标，不拥有运行状态。目标变更/失效时关闭或明确重新建立会话。
- 菜单动作执行前重新核对 ID 存在且权限/前置满足；ID 失效时退出并在可见位置提示，不能取“第一条可见行”作为替代。
- 列表重新排序/刷新不能用行下标保存目标，真实节点 ID 才是身份。取消弹窗不改节点、默认节点、分组和滚动位置。
- 没有选中节点时，“编辑/删除/设为活动/导出所选”等动作依原版禁用或反馈规则处理；不要把全部动作简单绑定一个 bool，也不要删除条目。
- 基础退出/焦点优先级修好后再核对原版按下/松开时机。不能为了避免闪烁在全局增加 100ms 等魔法延迟。

`AppTokens.toolbarHeight=32` 不等于工具栏实际为 32；本次测得 84。默认 token 的名字或注释不能代替布局测量。右键菜单更高、表单更紧的组合也说明“全部用 compact”没有形成统一的桌面密度。

## 排版执行约束

下列数值除明确标注上游的项目外是**待截图验收的初始建议**，不是假称原版已经实测的数据。全部使用逻辑像素，优先满足原版结构与内容可读性。

1. **先恢复结构，再调间距。** 依据 LAY-PROFILES-001 恢复顶部分组/过滤/图标；移出额外工具栏的动作必须仍能沿原版菜单与快捷键完成。主窗口三种布局、日志/连接区、状态栏和原有设置分组不能被重新设计成另一套导航。
2. **节点表保持桌面密度。** 默认沿用 24/26/28 的行高选项；文字保持默认约12–13。不要为了显得宽松把所有行变成48。中文字体的 ascent/descent、粗体选中状态、焦点框必须不被裁剪；纵向留白按实际字形验证。
3. **菜单项默认对齐上游32高。** 图标/勾选预留列、文本列、快捷键列和子菜单箭头列分别对齐；初始左右内边距10–12，文字与快捷键净间距至少16。宽度按实际本地化字符串测量并限制在窗口可见边界，不能靠小字号或把所有行改为两行解决。超长帮助文字移到原有可见提示/tooltip，不把“受限范围未实现”等开发标记塞进产品标签；功能缺口仍要在台账登记。
4. **工具栏按原版图标控件30×30为起点。** 相邻图标外缘建议8净间距（来源于上游左右各4的 margin）；图标与文本组合建议6–8。分组与过滤区域之间用8–12区分。当前 Wrap spacing=2 不能覆盖大多数控件自己的默认最小尺寸，需统一实际按钮盒子后测量。
5. **表单不要复用表格行高。** 输入控件建议先试34–36高，字段间净间距8–12，分组间16。标签与控件净间距12–16，长标签可换行且整体顶对齐；错误文字/帮助文字单独排版，出现后不盖住下一字段。这里是建议值，逐协议对照原版确认，不强行套同一模板删字段。
6. **字体设置必须跨页面一致。** 建立统一文本样式来源，区分正文字体、标签、辅助文字、等宽内容。不要只改 Theme 而让局部 const TextStyle 继续锁12。默认保持原版字号层级，视觉改善通过字重、对齐和留白实现。如果可配置大字号与方案的紧凑行高范围发生冲突，登记规格缺口并提供测量方案，不能擅自截断文字或缩窄设置范围。
7. **保留空间换取明确反馈。** 保存/导入/测试结果必须在当前窗口可见，不用顶栏窄缝塞一长串内部信息。沿用原版入口位置，错误信息说清下一步；详细日志留在原有日志区。

验收至少覆盖：800×600 最小窗口、1200×800 默认窗口、宽屏；浅/深色；三种主窗口布局；Windows 100%/125%/150% 缩放；默认与用户可设置的大字号；中文长分组名、IPv6、长节点备注、长快捷键标签、表单错误。当前仅测到一组实际窗口，其他组合保持“未验证”。
